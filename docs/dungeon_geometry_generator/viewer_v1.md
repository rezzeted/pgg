# DungeonGeometryGenerator: превью F9 v1 (DungeonGeometryGeneratorViewer)

`src/apps/DungeonGeometryGeneratorViewer`: приложение превью уровня (requirements §7, F9) — 3D-вид
и вид сверху с наложением IR поверх наполненного уровня, плюс read-only
вкладка **Topo** — топология level-synth: 2D-план раскладки и граф переходов
по GUI-free модели `dungeon_geometry_generator::TopoModel` (N4). Своя логика только в приложении
(N4): библиотеки `dungeon_geometry_generator*` не трогает, рендер — `pgg_preview` (оффскрин sokol
+ орбит-камера), панели и оверлей — Dear ImGui. Тест: smoke-прогон в ctest
(`DungeonGeometryGeneratorViewer_smoke_layout`).

## CLI

```
DungeonGeometryGeneratorViewer [project.json] [--smoke]
```

Быстрый старт: `DungeonGeometryGeneratorViewer projects/demo/project.json` — демо-подземелье из
репозитория (L-зал, ворота, переходы камень|кирпич; см.
`projects/demo/README.md`).

- Без аргументов: стартовый экран — крупные кнопки **New** (модалка с путём
  нового файла; пишется минимальный валидный стартовый проект — entry —
  коридор — hall с дефолтными слотами — и открывается) и **Open** (модальный
  файловый диалог на чистом ImGui, `filedialog.h`, без нативных зависимостей:
  текущий каталог + Up, сначала каталоги (`[dir] …`, клик — войти), затем
  *.json (клик — выбрать, двойной клик — принять), редактируемое поле пути
  (Enter = Select), Select/Cancel, Esc закрывает; старт — каталог последнего
  выбранного файла, иначе `<корень>/projects`, иначе cwd, память на сессию) и
  список **Recent Projects** (persistent, до 8 записей, платформенный
  config-каталог — `%APPDATA%\DGGViewer` /
  `~/Library/Application Support/DGGViewer` /
  `${XDG_CONFIG_HOME:-~/.config}/dgg-viewer`, `recent_projects.txt`; хранятся
  абсолютные пути, «x» убирает запись). Ошибка загрузки — красным текстом на
  том же экране. Относительные пути (CLI, диалоги) ищутся сначала от cwd,
  затем от каталога последнего открытого проекта.
- Меню **Files**: New (Ctrl+N), Open (Ctrl+O), Save (Ctrl+S — активен при
  несохранённых правках: `save_project`, атомарная запись через .tmp, затем
  re-layout), Close (закрыть проект — возврат на стартовый экран), Exit.
  New/Open/Close/Exit при несохранённых правках идут через подтверждение
  Save/Discard/Cancel. Заголовок окна ОС: «DGG Viewer - <проект>» (для
  project.json — имя каталога-родителя, иначе stem файла) с «*», пока есть
  несохранённые правки.
- Drag-and-drop (где платформа позволяет; на X11 — через Xdnd): дроп
  project.json открывает его, заменяя текущий уровень. Дроп замороженного IR
  (снифф по подстроке `"dungeon-geometry-generator-ir/` в голове файла) отклоняется с ошибкой:
  вьювер IR не открывает, раскладка всегда генерируется из layout-яруса
  проекта (`build_catalog` → `LayoutGenerator`, attempts=4 →
  `build_ir_from_layout`). Замороженный IR (F5) — вход DungeonGeometryGeneratorCli.
- `--smoke`: тот же путь данных без окна и sokol (покрытие в ctest без GPU):
  одна строка статистики в stdout, exit 0; без проекта — usage + exit 2.
- Коды выхода: 0 — ок, 1 — ошибка данных (проект/fill), 2 — ошибка командной
  строки.

Наполнение — `fill_level` с живым `UnitCache` (F8), активы DungeonGeometryGenerator ищутся по
`assets/codes.pgg`: `./assets` от cwd, затем вверх от каталога исполняемого
файла, затем вверх от каталога проекта; слоты проекта дополнительно
отваливаются в `FillOpts::dungeon_geometry_generator_assets` (порядок корней — fill_v1).

## Панели

- **Сайд-панель** (рисуется только с загруженным проектом): секция Stats
  (путь проекта, статистика последнего fill — юниты, reused/reran, мс, размер
  кэша — кнопки Refill / Re-layout и маркер «modified — Files > Save
  (Ctrl+S)» при dirty), далее вкладки **Project** / **Inspect** и секция Log.
  Файловые операции (New/Open/Save/Close/Exit) живут в меню **Files** и на
  стартовом экране, в панель не дублируются.
- **Вкладка Project** (`project_tree.h`): read-only дерево проекта поверх
  загруженных `Project` + F2-каталога (Level хранит его в `catalog`,
  пересобирается на load/refill/re-layout): seed и статистика каталога
  (шаблонов/инстансов vs бюджет), Rooms (клик — выделение комнаты, общее с
  инфо-панелью; теги — в тултипе), Passages, Templates (генераторы
  rooms_rect/corridors с числом порождённых шаблонов + явные шаблоны), Fill
  (роли, переходы, side rules), Slots. Клик по шаблону или генератору
  открывает карточку в окне View.
- **Карточки шаблонов** (`template_view.h`): динамические вкладки окна View
  рядом с 3D/Top/Topo (closable, повторный клик в дереве поднимает уже
  открытую). Карточка шаблона: имя + бейдж explicit/parametric, канвас
  контура в клетках (pan/zoom/Fit, как у Topo-панелей), использование —
  комнаты графа с подходящей ролью и комнаты текущей раскладки с этим
  шаблоном (клик — выделение). Карточка генератора: диапазоны и роли, сетка
  превью порождённых шаблонов (клик по превью — карточка инстанса).
  **Редактирование (write):** явный шаблон — роли, трансформации (первый
  чекбокс делает список явным), simple-двери (override length/corner), fill-
  override'ы; генераторы — диапазоны размеров/длин, custom-роли rects, общие
  door_length/door_corner_distance/catalog_budget. Правки пишутся в
  `level.project` в памяти (каталог и канвас обновляются после применения);
  «Save & Re-layout» в карточке / Ctrl+S / Files > Save вызывает
  `save_project` (атомарная запись через .tmp) и relayout — перечитка файла
  валидирует записанное. Правка доступна, пока проект загружен; dirty-флаг
  виден в меню-баре, заголовке окна («*») и сайд-панели. Контур и
  manual-двери пока read-only (редактор контура — отдельная итерация).
- **Виды 3D и Top** — вкладки одного окна справа от сайд-панели (область не
  делится пополам); активна по умолчанию **3D**, оффскрин-рендер идёт только
  у активной вкладки.
- **3D**: level-меш целиком (vertex colors из `@Cd`), орбита/pan/zoom мышью,
  Fit. Здесь же живут подсветка и соло юнита.
- **Top**: второй `GeometryPreview` в проекции `OrthoTop` (+X вправо, +Z вниз,
  §5.1) с тем же мешем; поверх — оверлей ImGui draw list через проекцию
  `viewProj` топ-превью. Слои-чекбоксы: контуры+id комнат, двери (зелёные
  open, оранжевые прочие dtype), владельцы стен, владельцы узлов, якоря
  (ромбики; `@label` — при наведении). Дефолт: комнаты/двери/якоря включены,
  владельцы выключены. Выделение рисуется отдельным ярким проходом независимо
  от слоёв.
- **Topo** — вкладка поверх `dungeon_geometry_generator::TopoModel` (проекция графа + раскладка,
  `src/libs/dungeon_geometry_generator/topo`), две бок-о-бок панели с независимыми камерами,
  порядок всех списков детерминирован (N6). Панель **Plan** — 2D-план в
  клетках world grid (ярус раскладки, не метры): контуры комнат/коридоров
  (без заливки — L-комнаты не выпуклые), отрезки дверей на общих рёбрах
  (зелёные open, оранжевые прочие dtype), id и роль в центроиде; слои
  rooms/ids/doors/roles. Панель **Graph** — граф переходов в стиле
  GraphCanvas PggViewer: боксы узлов 88×36 pt в центроидах комнат (id + роль,
  заливка и обводка цветом роли), bezier-провода узел→узел цветом dtype,
  метка dtype на середине (тёмная плашка), фон `#181b20`; комнаты графа без
  раскладки не рисуются, список «unplaced: …» — под холстом. Обе панели:
  pan (drag ЛКМ/ПКМ/СКМ), zoom к курсору (колесо), Fit (автофит по контурам /
  по боксам), клик по комнате — выделение (общее с инфо-панелью), клик по
  пустому месту — сброс, двойной клик — фокус камеры панели на bbox комнаты.
- **Инфо-панель** (секция Selection вкладки Inspect, приёмка F9): клик ЛКМ по топ-вкладке
  (без drag'а) выбирает комнату (point-in-polygon), стену/дверь (< 0.5 м до
  отрезка) или узел (< 0.5 м). Показывает параметры объекта и происхождение
  каждого значения цепочкой F12 (`format_prov`): у комнаты h/style/floor/ceil/
  wall_t, у двери dtype/h/frame/thick; у стены — владелец/стороны/двери, у
  узла — владелец/грани. Кнопки: Focus (камера обоих превью на bbox объекта),
  Highlight unit, Solo unit.
- **Панель юнитов** (секция Units вкладки Inspect): `FillResult.units` группами по слоту,
  действия над выбранным — Focus (bbox точек спана), Highlight (временная
  points-группа на копии меша + `highlightGroup`, только 3D), Solo (под-меш
  спана через `topo::deleteByMask` с инвертированной маской, только 3D;
  «Back to level» возвращает уровень).
- **Log**: последние записи fill — юнитов, точек меша, мс, reused/reran;
  ошибки операций — красным.

## Операции

- **Refill (reload project)**: перечитывает проект с диска, пересобирает IR
  из того же `LayoutData` и наполняет через тот же `UnitCache` — в логе видно
  reused/reran (F8, D3). Камера сохраняется.
- **Re-layout**: generate заново (тот же seed, attempts=4) → новый
  `LayoutData` → IR → refill; неизменённые юниты приходят из кэша (приёмка
  D3). Камера перефокусируется на сцену.
- Обе операции сбрасывают выделение и выбор юнита (id/спаны пересобираются).

## Лимиты v1

- Пикинг только в топ-вкладке; в 3D-виде выбора нет.
- Topo и дерево проекта — только просмотр (drag-узлов нет); карточки
  шаблонов/генераторов редактируют поля проекта (роли, трансформации, двери,
  fill, диапазоны), но не контур и не manual-двери (редактор контура — позже);
  позиции узлов графа = центроиды раскладки, force-directed раскладки боксов
  нет — на плотных уровнях боксы в фит-зуме перекрываются, зум вперёд их
  разводит (размер боксов фиксирован в пикселях).
- Якоря — только в оверлее топ-вкладки (в 3D-рендере не рисуются).
- Замороженный IR не открывается — раскладка всегда генерируется из проекта
  (чтение dungeon-geometry-generator-ir/* остаётся в DungeonGeometryGeneratorCli).
- Раскладка синхронна (малого уровня — быстрая); отмены из UI нет
  (F3-хук `request_cancel` в библиотеке есть, асинхронность — позже).

## Тесты

- `DungeonGeometryGeneratorViewer_smoke_layout`: `--smoke src/apps/DungeonGeometryGeneratorViewer/smoke_project.json`
  (генерация раскладки → IR → fill). Свой фикстурный проект, потому что
  `src/tests/data/d2_project.json` IR построить не может: роль corridor в нём
  переопределяет wall_t, и общие стены коридора с комнатами дают конфликт
  толщин — ошибку F4 по 5.2 (by design).
