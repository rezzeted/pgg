# План работ для агента: итерация 0 «Базовая линия»

Основание: [port_parity_roadmap.md — § «Итерация 0»](port_parity_roadmap.md) (пункты про DoD, матрицу тестов, опциональный golden и блок «Тесты после итерации»). Контекст расхождений: [port_vs_original_gap.md](port_vs_original_gap.md).

**Не делать:** рефакторинг констрейнтов, SA, дверей, новые алгоритмы — только артефакты, документация и минимальные правки тестов, если без них DoD не привязан к коду.

---

## Задача 1 — Definition of Done (зафиксировать в репо)

**Соответствует роадмапу:** «события SA, суммы штрафов на эталонных уровнях, допустимые позиции из КП для пары шаблонов».

**Действия агента:**

1. Создать **`docs/parity_dod.md`** с таблицей строк (пример колонок):
   - `ID` (D1, D2, …)
   - `Критерий` (кратко: воспроизводимость по seed; нет overlap на эталонных графах; события SA; энергия zero / incident≈2×total; опционально — одна метрика как в C# для КП/позиций)
   - `Проверка` — имя `TEST(...)` в [`src/tests/edgar_tests.cpp`](../src/tests/edgar_tests.cpp) или [`edgar_parity_tests.cpp`](../src/tests/edgar_parity_tests.cpp), либо «TBD» с пометкой, какой тест добавить позже (без обязательства в ит. 0, если достаточно ссылки на ближайший существующий)
2. Явно перечислить **эталонные мини-уровни** в тексте (какие `TEST` считаются эталоном для D2/D3), чтобы дальше не спорить, «какой граф эталонный».

**Готово, когда:** файл существует, у каждого заявленного критерия есть тест или осознанный TBD.

---

## Задача 2 — Матрица тестов C# → C++

**Соответствует роадмапу:** `Edgar.Tests` / `GeneralAlgorithmsTests` / `IntegrationTests` (`_edgar_ref`) → существующие или новые `TEST` в C++.

**Действия агента:**

1. Обойти все файлы **`*Tests.cs`** в:
   - `_edgar_ref\src\Edgar.GeneralAlgorithmsTests\`
   - `_edgar_ref\src\Edgar.Tests\`
   - `_edgar_ref\src\Edgar.IntegrationTests\`
2. Создать **`docs/test_matrix_iteration0.md`**: на каждый файл (или на крупный файл — несколько строк по подобластям) колонки:
   - `upstream_file`
   - `coverage`: `full` | `partial` | `none` | `na`
   - `cpp_TEST` — имена тестов или «—»
   - `notes` — что закрыть в итерациях 1+
3. В конце файла — **сводка**: сколько full / partial / none / na.

**Готово, когда:** все три дерева обработаны, нет пустой «дыры» без строки для файла `*Tests.cs` (кроме `AssemblyInfo.cs` и служебного).

## Задача 3 — Опционально: заготовка golden-пайплайна

**Соответствует роадмапу:** «общий вход описания уровня → сравнение структуры layout C# и C++ с допусками».

**Действия агента (минимум, если полный прогон C# не делается):**

1. Каталог **`test_data/parity/`** в корне репо.
2. Файл **`test_data/parity/README.md`**: договорённость о формате входа (например фрагмент YAML/JSON уровня), что **ожидаемый** выход может быть ручным снимком; полный автоматический дифф C#↔C++ — отложен.
3. При возможности без тяжёлой автоматизации: один **фиктивный** или реальный мини-пример входа + подпись «эталон layout — TODO / вручную».

**Готово, когда:** README есть; golden-скрипт не обязателен на ит. 0.

## Задача 4 — «Тесты после итерации» (артефакты в репозитории)

**Соответствует роадмапу:** таблица C#→TEST или TODO в `docs/` или `src/tests/README`; чек-лист DoD; при наличии скрипта — smoke golden.

**Действия агента:**

1. Убедиться, что **таблица** — это `docs/test_matrix_iteration0.md` (задача 2), а **чек-лист DoD** — `docs/parity_dod.md` (задача 1).
2. Создать **`src/tests/README.md`**: как собрать и запустить тесты (`ctest -C Debug`), прямые ссылки на оба файла выше; одна строка «итерация 0 закрыта, когда матрица + DoD заполнены и ctest зелёный».
3. Скрипт smoke golden — **опционально**; если нет — в README явно «скрипт golden — не в ит. 0».
