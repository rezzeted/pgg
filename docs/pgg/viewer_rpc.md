# PggViewer RPC + MCP (`pgg`)

_Контракт агентского RPC вьювера (этапы A1–A3, C2, D3, E, F1–F5 из `docs/pgg/agent_tooling_plan.md`). Правя соответствующий код (`src/apps/PggViewer/ViewerRpcServer.cpp`, `main.cpp`, `FrameCompare.{h,cpp}`, `tools/pgg_mcp/`), обновляй **этот** документ._

`PggViewer [file] --serve[=host:port]` поднимает TCP RPC-сервер на `127.0.0.1:9878` (построчный JSON, команды на GUI-потоке через `poll()` в `frame()`; занятый порт — ошибка в лог, живём без сервера). Реализация: `src/apps/PggViewer/ViewerRpcServer.h/.cpp` (транспорт, диспетч) + `registerPggViewerRpcHandlers` в `src/apps/PggViewer/main.cpp` (команды). Конверт: запрос строка `{"op":"…","args":{…}}`, ответ строка `{"ok":true,"data":{…}}` | `{"ok":false,"error":{"kind","message"}}`.

Операции:

- **Сессия:** `ping` → `{pong, app, protocol}`; `status` → `{file, params, cache:{size,capacity,hits,misses}, preview:{target,has_value}, uptime_s}`.
- **Файл и параметры:** `load {path|source, lib_roots?}` — `source` пишется в `tmp/pgg_rpc_source/src_N.pgg` (mkdir -p) и дальше идёт как `path`; ответ — статическая проверка без прогона (closure → expand → typecheck): `{diagnostics:[{code,line,col,warning,message}], has_errors, ms, path}`, невалидный файл отвечает за миллисекунды. `params {name:value}` — те же поля, что панель Params и `--param` (массив → вектор `(x, y, z)`), неизвестные имена — в `unknown` ответа.
- **Прогон:** `render {node, view?, out?, orbit?, zoom?, distance?, highlight?, shading?, colors?, size?, target?, fit?, ortho?, wire?, frame?, chrome?, compare?, png?, save_baseline?}` → `{path?, width, height, frame, chrome, size_clamped?, node, stats, diagnostics, camera:{center,radius,distance,target_bbox?}, render_state:{wire,chrome,ortho,target,zoom,fit}, cache, reloaded, load_diagnostics?, compare?}`. **Stateless (C5):** незаданный параметр берёт дефолт (`wire=false`, `ortho=off`/perspective, `target=""`, `highlight=""`, `shading=auto`, `colors=on`, `chrome=on`, `zoom=1` если нет `zoom`/`distance`/`orbit[2]`), а не прошлое. Липкие только `orbit` (yaw/pitch) и `distance`. `view` подставляет поля из `<stem>.views.json` (явные args перекрывают). `png:false` — без записи основного PNG и без `path` (пиксели для compare всё равно снимаются). `compare` — `"prev"|"baseline"`; `save_baseline:true` или первый `compare=baseline` без слота создаёт visual baseline (ключ = frameKey); `load` сбрасывает его. Прогон без значения — `run_failed`; с E-диагностиками — `run_errors`. `probe {spec}` → `{records, diagnostics, has_errors, ms, cache, reloaded, load_diagnostics?}` (инспекторы в т.ч. `bbox[group=…]`, `gap[a=,b=,axis=]`); `export {node, obj_path}`; `docs {symbol}` — def загруженного файла, иначе fallback в реестр билтинов без префикса `builtin:` (успех `kind:"builtin"`; промах — `not_found` + did-you-mean); `views {}` → `{file, views:[…]}`.
- **Diff прогонов (C2, серверный `pgg_diff`):** `diff {update?}` — fp-level сравнение outputs текущего файла с сессионным снимком фингерпринтов (структурный fp `fingerprintValue`, тот же что у `PggTool run --fingerprint`/`diff`; без ΔP — таблица изменений остаётся у CLI). **Снимок:** создаётся первым `diff` (ответ `{baseline_created:true, outputs:[{name,fingerprint}]}` — сравнения нет) или `load {..., snapshot:true}` (прогон outputs на load; в ответе `snapshot:true`, битый файл — `snapshot:false`); **обновляется только** `diff {update:true}` (`snapshot_updated:true`) и **сбрасывается явным `load`** (новый контекст документа). Авто-reload (F4) снимок НЕ сбрасывает: он срабатывает внутри `diff` перед прогоном, как у probe/export — правка файла на диске ловится именно diff'ом. Ответ сравнения: `{baseline_created:false, identical, outputs:[{name, status: identical|changed|added|removed|skipped, fingerprint_prev, fingerprint_now, note?}], snapshot_updated, reloaded, load_diagnostics?, ms, cache}`; `skipped` — sdf/field-выходы без структурного fp, на `identical` не влияют (как в `PggTool diff`). Ошибки прогона — конверт `run_errors`, снимок не трогается. Типовой цикл: `diff` (baseline) → правка файла → `diff` → `changed` по затронутым outputs → `diff {update:true}`, когда новое состояние принято.

  **Кадр render (F1):** `frame` — `"preview"|"window"`, **по умолчанию `preview` для RPC** (CLI `--shot` — `window`, флаг `--shot-frame=preview|window`): `preview` кропит readback до вьюпорта превью-панели — точный rect картинки в физических пикселях (логические координаты ImGui × `sapp_dpi_scale()`; без боковой панели, графа и строки тулбара превью), GL-readback перед кропом приводится к top-down рядам, как у остальных бэкендов. `chrome="off"` — один кадр без панели и графа: превью-панель растягивается на всё окно (в `frame()` пропускаются drawPanel/drawCanvasWindow/drawSplitter), так что кроп `frame=preview` ≈ всё окно — больше пикселей модели при том же окне; на следующий кадр хром возвращается. Окно программно **не ресайзится** (sokol не умеет на всех бэкендах), поэтому `size` в режиме `frame=preview` — целевой размер кропа в пикселях PNG: кроп центрируется на вьюпорте и клампится к его фактическому rect'у (апсайз без FBO невозможен, §6 плана); если урезано — в ответе `size_clamped:true`. Совместимость: в режиме `frame=window` `size` — прежняя позиция сплиттера превью-панели (пункты, не пиксели).

  **Сравнение кадров и референс (F3):** `render {..., compare:"prev"|"baseline"}` — в ответ добавляется `compare` с diff-метриками против **предыдущего кадра того же вида**. Ключ вида — узел + **эффективное** состояние камеры (center/radius/distance/yaw/pitch/projection/fit после применения аргументов и рефита) + frame/chrome + опции превью (highlight/shading/colors/wire/sdf voxels); значения `params` и правки файла в ключ **не входят** — именно их compare и показывает. Хранится **один** последний кадр (`g_lastFrame*`, ~8 МБ), заменяется каждым успешным `render` (с compare или без); `reference` его не трогает. `compare:"baseline"` — карта кадров по тому же `frameKey`, не вытесняется каждым render; `save_baseline:true` или первый `compare=baseline` без слота создаёт снимок (`baseline_created`); `load` сбрасывает visual baseline. Ответ `compare`: `{available, changed_pct (0..100), change_bbox_px:[x0,y0,x1,y1] (exclusive; нули при 0 изменений), diff_png}`; `available:false` с `reason` — `"no previous frame"` (первый кадр вида или смена вида) или `"size mismatch (prev WxH, now WxH)"`. Пиксель «изменён», когда максимальная разница по каналам > 8/255 (альфа игнорируется). `diff_png` — `tmp/pgg_rpc_shots/diff_N.png`, пишется при каждом доступном сравнении (при 0 изменений — просто затемнённый кадр): новый кадр ×0.3, изменённые пиксели — magenta. Типовой цикл: `render(node)` → правка файла/`params` → `render(node, compare="prev")` → `changed_pct`/`change_bbox_px`/`diff_png` отвечают на «правка попала туда, куда я целился?». CPU-ядро — `FrameCompare.{h,cpp}` (`compareFrames`, детерминировано, покрыто смоуком на синтетике).

  `reference {image, node, ortho?, orbit?, zoom?, size?}` — модель рядом с референсом. Прогон узла как у `render` (те же ошибки `run_failed`/`run_errors`/`busy`, авто-reload F4 с `reloaded`/`load_diagnostics`), но с детерминированным ракурсом: запомненный target сбрасывается, fit принудительно `all` по всей сцене (`g_preview.fit()` после runPreview — повторный вызов на том же узле кадрирует так же), `ortho` по умолчанию `front` (`side`/`top`/`off`|`perspective`; orbit/zoom — те же множители, что у render). Кадр всегда `frame=preview` (фон известен точно — clear-цвет превью `GeometryPreview::kClearColor`); `size` — как у render frame=preview (кламп + `size_clamped`). Фаза 2 не пишет model-only PNG (кадр остаётся в памяти): `composeSideBySide` клеит `модель | разделитель 4px (серый 90) | референс` в один PNG высоты кадра модели (референс ресайзится bilinear с сохранением аспекта; ресайз руками, детерминированный — stb_image_resize2 не используется) → `tmp/pgg_rpc_shots/ref_N.png`. Ответ: `{path, width, height, node, model:{bbox_frac:[x0,y0,x1,y1], w_over_h, rows:[10], empty}, reference:{...}, reference_background:[r,g,b], ms, stats, diagnostics, camera, cache, reloaded, load_diagnostics?}`. Силуэт = пиксели, отличающиеся от фона > 8/255 по любому каналу; фон модели — точный clear-цвет превью, фон референса — мажоритарный RGB 4 углов (`estimateBackground`, при равенстве — первый угол в порядке TL,TR,BL,BR; возвращается в `reference_background`). `bbox_frac` — bbox силуэта в долях кадра (x1/y1 exclusive); `w_over_h` — ширина/высота bbox в пикселях; `rows` — 10 равных горизонтальных полос сверху вниз, в каждой средняя доля ширины силуэта (fg-пиксели полосы / пиксели полосы). Чтение референса — `stbi_load` (STB_IMAGE_IMPLEMENTATION живёт в FrameCompare.cpp, единственный TU вьювера). Ошибки: `image` не читается → `invalid_input` (до прогона и кадра); headless → `no_frame_loop` (гейт до разбора аргументов, как у render).

  **Камера render (A2 + C2/C5):** `target` — строка `"x,y,z" | "group:<имя>" | "binding:<путь>"`: центр орбиты и (при `fit=target`) fit по цели, остальная сцена остаётся в кадре по fit-дистанции цели. `group:` берёт bbox группы из per-group bbox'ов свежего прогона (имя с доменом `"faces:roof"` или голое `"roof"` — суффикс-матч, неоднозначность → первая по сортировке + warn); `binding:` делает отдельный pull пути по тёплому кэшу и берёт bbox его геометрии (тот же path, что у пробника: top-level, instance path, `<ipath>.<local>`; `/` → `.`). `group:<grp>@<binding>` — pull биндинга, bbox группы **внутри него**. В `camera.target_bbox` — `{min,max,center}` того, во что попали; точка `x,y,z` — центр орбиты при scene-радиусе. **Неразрешённый target — ошибка `target_unresolved`** с причиной и списком групп превью (не тихий откат на `fit=all` с не той картинкой); target при этом сбрасывается, следующий `render` без него не застревает. В CLI тот же случай — warn + откат на `fit=all`. **Авто-ракурс:** если в этом `render` не задан `orbit`, yaw поворачивается так, чтобы камера стояла со стороны цели относительно центра сцены (`faceTargetFromOutside`: `yaw = atan2(dx, dz)` вектора центр сцены → центр цели; цель у центра сцены, < 0.1·радиуса по горизонтали — yaw не трогается; в орто-видах не применяется) — иначе цель на фасаде снималась изнутри дома через заднюю стену. Явный `orbit` (или `--preview-orbit` в CLI) авто-ракурс отключает. `fit` — `"all"|"target"` (дефолт: `target`, если задан `target`, иначе прежний режим). `ortho` — `"front"|"side"|"top"|"off"`: ортопроекция по оси со снапом ракурса (front = камера на +Z, side = на +X, top = сверху +Y; yaw/pitch пользователя сбрасываются в предустановку, мышь потом крутит как обычно). `wire` — bool: тёмный line-list рёбер поверх шейдинга (dedup по рёбрам, мелкий z-bias вместо polygon offset). **Stateless (C5):** без `target` цель сбрасывается (fit=all); липкие только orbit yaw/pitch и `distance`; факт — в `render_state`. Третий компонент `orbit` и именованный `zoom` — множитель fit-дистанции (`distance = radius·2.6·zoom`): 1 — вписать цель в кадр, 0.5 — вдвое ближе, 3 — втрое дальше; `zoom` перекрывает `orbit[2]`, когда заданы оба. `distance` — дистанция от центра орбиты в метрах: применяется после резолва `target` (т.е. точно от центра цели), перекрывает `zoom`/`orbit[2]` и переживает последующие рефиты как эквивалентный множитель fit-дистанции. `camera` в ответе — фактическое состояние после применения: `center` (центр орбиты — у group-target центр bbox группы), `radius` (радиус активного fit), `distance`.

  **Авто-reload по mtime (F4):** перед прогоном `render`/`probe`/`export` сервер статит mtime главного файла и всех модулей его import-closure (canonical путь главного + `ModuleClosure.modules[].canonicalPath`, снятые при последнем `loadFile`). Изменился хоть один → сначала `loadFile(g_filePath)` (перечитываются граф, панель диагностик и набор param'ов — как у явного Reload; значения, выставленные командой `params`, при этом сбрасываются в дефолты файла, ровно как при явном `load`), в ответ добавляются `reloaded:true` и `load_diagnostics:[{code,line,col,warning,message}]` (пустой массив при чистой загрузке). Без изменений — `reloaded:false`, `load_diagnostics` отсутствует. Ошибки загрузки (парс/импорты) — `ok:false` с `kind:"run_errors"` и списком диагностик в message, прогон НЕ выполняется (битый файл не должен отдавать картинку половины сцены — та же конвенция, что у рантаймовых ошибок render). Не отслеживается: `load{source}` — temp-файл `tmp/pgg_rpc_source/src_N.pgg` снаружи не правится (источник приходит целиком в RPC), для него авто-reload пропускается (`reloaded:false` всегда). Фактология: сами прогоны и до F4 читали файл с диска свежим (`pgg::runFile` перечитывает и перепарсивает файл с импортами на каждый вызов) — устаревали состояние вьювера (граф, диагностики, набор param'ов) и запиненные значения параметров (дефолт, снятый при load, передавался в прогон как явное значение, поэтому правка дефолта в файле без load была невидима).

Грабли: `render` **двухфазный и синхронный** — прогон в poll-фазе блокирует frame loop на всё время, ответ приходит из `frame()` после первого закоммиченного кадра с новой геометрией; `out` по умолчанию `tmp/pgg_rpc_shots/shot_N.png`, PNG по умолчанию — кроп вьюпорта превью (`frame=preview`, F1; `frame=window` — весь кадр окна); параллельный render — ошибка `busy`. render требует UI-режим: с `--no-ui`/`--smoke` отвечает `no_frame_loop`. `probe`/`export` тоже синхронные. macOS: poll() живёт в frame(), поэтому при залоченном экране кадры не тикают и RPC стоит целиком (idle sleep/App Nap вьювер давит сам через `beginActivity`, лок экрана это не лечит). Сессионный `MemoryCache` (4096) переживает `load` того же файла: правка инвалидирует только downstream — но зоны repeat/foreach кэшем пропускаются by design, поэтому тяжёлые зональные графы (cottage_mansard) тёплым прогоном не ускоряются.

MCP-обёртка: серверы `pgg` (macOS/Linux, sh) / `pgg-win` (powershell) в `.mcp.json`, код — `tools/pgg_mcp/` (FastMCP stdio, инструменты `pgg_status/pgg_load/pgg_params/pgg_render/pgg_probe/pgg_export/pgg_diff/pgg_docs/pgg_reference/pgg_views/pgg_contact_sheet/pgg_measure`, ответ RPC as-is; `pgg_load` принимает необязательный `snapshot` для baseline'а `pgg_diff`; `pgg_render` — `compare="prev"|"baseline"` (F3); лаунчеры `tools/run_pgg_mcp_server.{sh,ps1}`). В отличие от editor MCP, **viewer поднимается автоматически**: если порт 9878 не отвечает, ищется бинарь (env `PGG_VIEWER` → `_int_clion_release/.../Release/PggViewer` → `_int_clion/.../Debug/PggViewer` → `_intermediate_64/.../Debug/PggViewer`; предпочтение Release — он в разы быстрее), `Popen([viewer, "--serve"])` (на Linux без DISPLAY — `xvfb-run -a`), ожидание порта до 30 с; лог viewer'а — `tmp/pgg_viewer_serve.log`. Типовой цикл: `pgg_load` → `pgg_render` → чтение PNG файлом → `pgg_probe` → правка файла → сразу `pgg_render`/`pgg_probe` (F4: авто-reload по mtime подхватывает правку сам, тёплый кэш инвалидирует только downstream; явный `pgg_load` нужен только для `source`, смены файла или немедленной статической проверки).
