# Улучшение инструментов отладки для агента — план работ

**Статус:** A1–A3, B1–B3, C1–C2 реализовано (2026-09-08); F1–F2, F4, D1–D3, B4–B5, E, B6 реализовано (2026-09-09); C3–C4 + pgg_diff в сервере реализовано (2026-09-09); остальное — план. Этап F (2026-09-09) — пункты по итогам первой реальной сессии на готовом MCP (`lamp_fence.pgg`): что мешало, когда цикл уже стал быстрым. Объединяет предложения по PggTool/PggViewer и по MCP-серверу для итеративного цикла правок. Каждый пункт привязан к конкретному инциденту последних сессий, где агент упирался в инструмент и делал работу в обход (numpy вместо сэмплирования поля, `cmp` по OBJ вместо diff'а, `xvfb-run` с ручным подбором орбиты и `--shot-delay=14` вслепую).

## 0. Постановка

Главный пользователь PGG — кодинг-агент. Он не крутит модель мышкой и не ставит брейкпоинт: единственный способ **увидеть** результат — задать вопрос инструменту и прочитать ответ. Критерий качества инструментария — сколько вопросов агент может задать за один вызов, насколько ответ детерминирован и diffable, и сколько секунд длится цикл «правка → картинка + числа».

**Текущий цикл** (замерено на `cottage_mansard.pgg`, узел `house`):

| Шаг | Как сейчас | Время |
|---|---|---|
| проверка синтаксиса/типов | отдельный `PggTool check` (агент часто пропускает) | 50 мс |
| картинка | `xvfb-run PggViewer f --preview=house --preview-orbit=… --shot=… --shot-delay=14` | ~20 с (старт + полный прогон 16 с + слепая задержка) |
| нацелить камеру на деталь | нельзя (орбита вокруг bbox всего дома); обход — `--preview=door` без контекста | 2–3 итерации |
| числа по узлу | `PggTool run … --probe/--obj` — ещё один полный прогон, кэш не переживает процесс | 16 с |
| проверить «ничего не сломал» | `PggTool run --obj` ×2 + `cmp` | 2×16 с + ручной разбор |
| значения поля/SDF в точке | **нет** — переписывание SDF на numpy | ~час |
| здоровье меша (вырожденные грани, non-manifold) | **нет** в CLI — только внутри голден-тестов | 2 мин прогона `tower` |

Итого одна итерация — 30–60 с и 3–4 вызова инструментов; половина времени — повторные полные прогоны одного графа, потому что кэш (`MemoryCache`, §5.3 спеки) живёт только внутри процесса.

**Что уже есть и на что опираемся:** контракт пробников `path:inspector[param=value,...]` с инспекторами `schema · stats · coverage · table` (§9, E6); `PggTool run/check/fmt/ast/docs`; `PggViewer` с `--preview/--preview-orbit/--preview-highlight/--shot`, причём `--shot` читает кадр из GPU на всех бэкендах (`95e079a`: `glReadPixels` / readback drawable на Metal / backbuffer на D3D11) — offscreen-рендер не нужен; паттерн TCP RPC (построчный JSON, команды на GUI-потоке) и MCP-обёртка `tools/pgg_mcp/server.py`.

## 1. Этап A — сервер `PggViewer --serve` и MCP `pgg` (главный множитель)

**Цель:** правка файла → один MCP-вызов → картинка нужного узла + его статы + диагностики, за секунды, по тёплому кэшу.

**Почему не обёртка над CLI:** подпроцессы на каждый вызов экономят только токены на командные строки. Выигрыш даёт **постоянный процесс**: один загруженный движок с `MemoryCache` (правка цвета ставней пересчитывает только хвост после `windows`, а не 16 с всего дома), один GL-контекст на сессию (нет старта Xvfb/окна на каждую картинку), диагностики до тяжёлого прогона.

### A1. RPC в PggViewer

**Статус: реализовано (2026-09-08).** Уточнения по ходу: `load{source}` — через temp-файл `tmp/pgg_rpc_source/src_N.pgg` (in-memory путь не понадобился: все потребители читают файл с диска); `render` — двухфазный (poll-фаза: опции + синхронный прогон; ответ из `frame()` после первого закоммиченного кадра с новой геометрией); CLI `--shot` с `--preview` без явного `--shot-delay` тоже по готовности кадра (явный `--shot-delay` — старое wall-time поведение); ёмкость сессионного кэша 4096, не 512 (cottage_mansard — ~2.2k кэшируемых binding'ов, LRU при 512 thrash'ил); измеренный эффект кэша честно таков: на беззонных графах тёплый прогон ≈ 0 (e4_sdf_rock), но cottage_mansard НЕ ускоряется (Debug `house`: 80.8 с холодный vs 101.4 с тёплый при 96 % hits) — фингерпринты зон repeat/foreach = 0 by design (E7), зональные binding'и кэшем пропускаются; закрытие этой дыры — отдельная работа за рамками A1; PNG — весь кадр окна (тот же `capturePng`, что у `--shot`), аргумент `size` у `render` двигает сплиттер превью-панели, а не ресайзит окно; `PggTool docs`/`writeObj` вынесены в `pgg::eval` (`docs_lookup`, `obj_export`) и разделены с RPC, заодно исправлен use-after-free qualified `docs`. При `--serve --no-ui` (или в `--smoke`) `render` отвечает ошибкой `no_frame_loop`.

- `PggViewer [file] --serve 127.0.0.1:9878` — TCP, построчный JSON, команды исполняются в `frame()` на GUI-потоке (как в редакторе). Работает и с окном (человек видит то же, что агент), и под `xvfb-run`/`--no-ui`.
- Команды: `load {path | source, lib_roots}` → диагностики (код, строка, сообщение, путь binding'а) без прогона; `params {name: value}`; `render {node, orbit?, target?, highlight?, shading?, colors?, size?}` → PNG (путь или base64) + статы узла (kind, pts/tri, bbox, группы с числами граней); `probe {spec}` → записи инспекторов; `export {node, obj_path}`; `docs {symbol}`; `status`.
- **Захват по готовности, не по таймеру.** Сейчас `--shot` срабатывает по `--shot-delay` (wall-time). В сервере: команда `render` ставит цель превью → после завершения `runPreview` и первого отрисованного кадра с новыми параметрами — readback тем же `capturePng` → ответ. `--shot-delay` остаётся как override для CLI.
- Кэш прогона (`RunParams.cache`) — один на сессию, переживает `load` того же файла: перезагрузка после правки пересчитывает только изменившиеся binding'и.
- Файлы: `src/apps/PggViewer/main.cpp` (frame/serve), `src/apps/PggViewer/ViewerRpcServer.h/.cpp`, без новых зависимостей.

### A2. Нацеливание камеры

**Статус: реализовано (2026-09-08).** Уточнения по ходу: top-вид — это pitch **+90°** в конвенции орбиты вьювера (`eye = center + dir(yaw,pitch)·distance`: +90 ставит камеру НАД целью; плановое «pitch −90» ставило бы её под сцену), up на полюсе — `(0,0,−1)` (фасад остаётся внизу плана); полувысота орто-фруста — `radius·1.3·fitZoom` (множитель, не делитель — fitZoom это множитель дистанции: больше zoom = дальше камера = больше видно), `distance=` в CLI не стал отдельным флагом (есть у `setTarget` в API и выводится как `camera.distance`; третий компонент `--preview-orbit` закрывает zoom); `group:` без домена матчится по голому имени (неоднозначность → первая по сортировке + warn); `binding:` резолвится один раз на `load` (зональные графы тёплым кэшем не ускоряются, повторный pull на каждый rebuild был бы полной ценой прогона); wire — отдельный pos-only шейдер flat-color + line-пайплайн с z-bias в клип-пространстве (portable замена polygon offset), без домешивания в основной шейдер; в ответе `render` — `camera:{center,radius,distance}` фактического состояния. Доработка 2026-09-09: неразрешённый `target` в RPC — ошибка `target_unresolved` (с причиной и списком групп), а не тихий `fit=all`; без явного `orbit` камера автоматически ставится со стороны цели относительно центра сцены (`faceTargetFromOutside`) — раньше цель на фасаде снималась изнутри дома.

- `target` в `render` и `--preview-target=` в CLI: `x,y,z` | `group:<имя>` | `binding:<путь>` — центр орбиты и fit по bbox цели, остальная сцена остаётся. Плюс `fit=all|target`, `distance=`, `ortho=front|side|top` (ортопроекции сильно упрощают чтение размеров), `wire=on`.
- Файлы: `GeometryPreview.h/.cpp` (камера), `main.cpp` (флаги).

### A3. MCP-обёртка

**Статус: реализовано (2026-09-08).** Уточнения по ходу: автоподнятие ищет бинарь в порядке env `PGG_VIEWER` → `_int_clion_release` (Release) → `_int_clion` (Debug) → `_intermediate_64` (Debug) — Release предпочтителен, прогон коттеджа ~4 с против ~80 с в Debug; stdout/stderr viewer'а — в `tmp/pgg_viewer_serve.log` (наследовать stdio нельзя — сломает MCP-транспорт); таймаут клиента 600 с (render отвечает только после закоммиченного кадра). Контракт — `docs/pgg/viewer_rpc.md`.

- `tools/pgg_mcp/server.py`; запись `pgg` в `.mcp.json` (Linux/macOS: `sh`, Windows: `powershell`) — поднимает PggViewer с `--serve`, если порт не отвечает.
- Инструменты: `pgg_load`, `pgg_params`, `pgg_render`, `pgg_probe`, `pgg_export`, `pgg_docs`, `pgg_status`. Ответ `pgg_render` — картинка **и** числа в одном сообщении: картинка без чисел бесполезна, числа без картинки тоже.
- Документация: раздел в `docs/mcp_servers.md`, абзац в `implementation.md`, короткая строка в `AGENTS.md` («Инструменты»).

**Приёмка A:** цикл «правка `cottage_mansard.pgg` → `pgg_render(house, target=group:lamp)`» ≤ 5 с на тёплом кэше (первый прогон — как сейчас); невалидный файл — ответ с диагностиками за < 100 мс без прогона; смоук `PggViewer --serve … --smoke` в тестах приложения; `docs/pgg/implementation.md` обновлён.

## 2. Этап B — пробники для полей, SDF и здоровья меша

**Инцидент:** `mc_thin_shell_slivers.md` — чтобы увидеть, что «оболочка 0.12» на торце на самом деле стенка 1 см, а грань лежит ровно на узле решётки, потребовалось сэмплировать поле в точках; PggTool этого не умеет, автор брифа ушёл по ложной гипотезе, а корректный ответ занял бы одну команду. Там же: 12 % треугольников нулевой площади в оболочке крыши никто не видел, а 6 non-manifold рёбер от первой версии фикса всплыли только в двухминутном голден-тесте.

Все инспекторы — расширение существующего контракта `path:inspector[params]`, доступны и в `PggTool run --probe`, и в `pgg_probe` сервера; реализация — `engine.cpp`/`probe.cpp`, тесты — `probe_test.cpp`.

**Статус B1–B3: реализовано (2026-09-08).** Уточнения по ходу: vec-значения параметров пишутся **в скобках** — `at=(0,1,3.425)` вместо плановой `at=0,1,3.425` (иначе сплит по запятым неоднозначен; зафиксировано в спеке §9.6, сплит — по запятым верхнего уровня с учётом скобочной глубины, `make_rock[1]:sample[at=(0,0,0)]` разбирается правильно); geo-таргет `sample`/`slice` — **псевдо-знак** по нормали ближайшего треугольника (готовый оракул `MeshBvh::closest`, тот же, что у `sdf_from_mesh`), пометка в заголовке записи, не unsigned; **`slice` без PNG** (в pgg-lib нет stb, ASCII/CSV закрывают инцидент — `format=png,out=…` не реализован); `check`: **boundary рёбра и число компонент — информативные строки, в `issues` не считаются** (boundary — норма для открытых мешей, components>1 — норма для fracture/мержей); `limit` теперь валиден и для `check` (списки индексов), `aggregate` ограничен связкой schema/stats/coverage. Контракт — спека §9.6, реализация — `implementation.md`. Живая приёмка: репрокейс `mc_thin_shell_slivers.md` — `shell:slice[axis=z,at=3.425,step=0.25]` печатает треугольник щипца, на 3.40/3.45 — пусто; на текущей крыше `roof_all:check` → degenerate 13, needles 18610 (6.0 %), components 820, boundary 39, `multi_gable[0].deck:check` → degenerate 19 (float-нулевая площадь при edge_min 4.5e-08 — микрорёбра после побитовой сварки), needles 5.6 %, nonmanifold 0 — наблюдение зафиксировано, геометрия крыши сознательно не правилась.

**Статус B4–B5: реализовано (2026-09-09).** Уточнения по ходу: формула решётки вынесена из `meshFromSdfExtract` в общий хелпер `meshFromSdfLattice` (`sdf.h`) — экстрактор и `lattice` считают одну решётку бит-в-бит (рефактор без смены арифметики; прогон Sdf/MeshFromSdf/Tower/Repro — 19/19 зелёные, голдены не тронуты); `voxel` у `lattice` **обязателен** (у `mesh_from_sdf` дефолта нет — честный E606 вместо угадывания); якоря инстансов разворачиваются через трансформ, когда поворот — **знаковая перестановка осей** (перенос + uniform scale + кватернион, снапящийся к {0,±1}-матрице с eps 1e-5 — покрывает повороты на 90° из `gable_prism_z`), наклонные якоря пропускаются со строкой `note: K instance anchor(s) skipped (non-axis-aligned rotation)`; плоскости дедуплицируются по (узел, ось, координата), ничьи при сортировке — в порядке обхода DAG (указатели не сортируются). Stretch «W-код в `check` при mesh_from_sdf в графе» **не делался** (инспектор закрывает тот же вопрос явным вызовом). B5: предикат парсится как синтетический binding через публичный `pgg::parse` и компилируется против общего env (иденты → binding'и файла); выражения — ровно то, что умеет грамматика: **swizzle `.x` отсутствует** (идиома `dot(@N, (0, 1, 0))`), логические операторы — `&`/`|` (не `&&`/`||`); не-bool предикат — E606 с подсказкой, отсутствующий атрибут — рантайм E302 от предиката; `find` без `where` — E606 на этапе resolve (до pull'ов); `groups:` у `find` — **points-группы** с числом выбранных точек (зафиксировано в спеке §9.6). Контракт — спека §9.6 (v1.25), реализация — `implementation.md`. Живая приёмка: `tmp/mc_repro.pgg` (восстановлен из текста `mc_thin_shell_slivers.md`) — `shell:lattice[voxel=0.05]` печатает 16 warn'ов: плоскости коньков `y=2.93`/`y=3.43` лежат в 0.9 мм от плоскости решётки (фаза их НЕ спасает — честный сигнал), пары 1-см стенок оболочки (x ±2.92/±2.93, z ±3.42/±3.43 — торцы щипца, 0.00999999), совпадающие подошвы призм `y=0`/`y=-0.5` (d=0, разные примитивы), перекрёстные пары main/wing (0.05–0.06) + `note: 8 instance anchor(s) skipped` (45°-скаты обеих оболочек); `house:find[where=@ao < 0.9]` на cottage — count+bbox+groups, `house:table[where=...,limit=3]` фильтрует строки. Тесты — `probe_test.cpp` секции 14–15 (48/48 Probe зелёные).

- **B1. `sample`** — значение в точках: `shell:sample[at=0,1,3.425]`, несколько точек через `;`, профиль `sample[from=…,to=…,n=41]`. Для `sdf` — поле; для `geo` — ближайшая точка/грань и расстояние (для мешей — псевдознак `sdf_from_mesh`, помеченный). Вывод `x y z value` построчно, `%g`.
- **B2. `slice`** — срез поля: `slice[axis=z,at=3.425,step=0.25]` → ASCII-карта (`#` внутри, `.` снаружи; для агента текст в контексте важнее PNG), `format=csv` — значения, `format=png,out=…`. Границы — conservative bbox или `bounds=`.
- **B3. `check`** — здоровье меша: вырожденные грани (нулевая площадь / повторные индексы), non-manifold и boundary рёбра, изолированные точки, NaN/inf в `@P/@N/@Cd`, компоненты связности и несогласованная ориентация по компонентам, min/median ребра, доля «иголок» (`warn_aspect=20`).
- **B4. `lattice`** — решётка `mesh_from_sdf` глазами автора: `shell:lattice[voxel=0.05]` печатает начало/шаг/размеры и предупреждает про осевые грани примитивов DAG ближе 0.05·voxel к плоскости решётки и пары параллельных граней на расстоянии < 2·voxel (кандидат на пропадание/рвань). Та же эвристика — как W-код в `check`, когда в графе есть `mesh_from_sdf`.
- **B5. `table[where=<поле>]` и `find[where=…]`** — отфильтрованные строки (предикат — обычное поле PGG, парсер и eval уже есть) и быстрый ответ «сколько и где» (count, bbox подмножества, группы).
- **B6. `--eval '<expr>' --on <binding>`** — вычислить произвольное поле в контексте файла на заданной геометрии и прогнать через инспекторы (синтетический binding поверх `FlatProgram`, семантика `set(on, "tmp", expr)`); закрывает «какой разброс у этого шума на самом деле» без правки файла. **Статус: реализовано (2026-09-09).** Уточнения по ходу: выбранная семантика — expr парсится синтетическим binding'ом `__eval__ = (<expr>)` и компилируется против общего env файла (механика B5 `where`: иденты → binding'и файла, `@attr` → поле), вычисляется `evalField` на **points-домене** on-геометрии (константа бродкастится на все N точек), материализуется атрибутом `@__eval` на копии геометрии и печатается инспектором **stats** (единственный инспектор, без `--eval-inspector`): запись `eval <on>: <expr> = <тип> on N pts` + строки `__eval[.x/.y/.z]: mean …, p50 …, p90 …, min …, max … (N pts)` (vec — покомпонентно). `--on` принимает пробниковый синтаксис путей (binding / instance path / безындексный def — по записи на каждый таргет; attr-терминал — E606). Ошибки: `--on` не найден → E606 (та же resolve-диагностика, что у пробников), не-geo таргет / string-выражение / поле-таргет → E606, `--eval` без `--on` (или наоборот) → usage, exit 2. **`--eval` не сужает прогон**: outputs считаются как обычно (сужение — через `--output`/`--probe`). Записи — ProbeRecord с origin `eval`, в `--json` попадают в массив `probes`. Реализация — `executeEval` в engine.cpp, `RunParams += evals`; тесты — `eval_profile_test.cpp`.

**Приёмка B:** для каждого инспектора — команда из инцидента и её ожидаемый вывод фиксируются тестом; `slice` на репрокейсе из `mc_thin_shell_slivers.md` показывает треугольник щипца на `z = 3.425` и пусто на `3.40/3.45`; `check` на нём же до фикса `5cacc1b` дал бы `degenerate 15458`, после — малое число (фактически на 2026-09-08: `roof_all` → 13, SDF-настил `deck` → 19 — float-нулевая площадь на микрорёбрах, индекс-вырожденных нет; см. статус B1–B3 выше); контракт инспекторов — в §9 спеки, реализация — в `implementation.md`.

## 3. Этап C — сравнение прогонов и голдены

**Инцидент:** каждая декомпозиция `cottage.pgg` проверялась `cmp` двух OBJ; при отличии `cmp` говорит только «байт N». Фикс фазы решётки означал ручное переснятие 40 литералов в `*_test.cpp` скриптом по gtest-выводу.

Силуэтные метрики обеих половин: `{bbox_frac, w_over_h, rows[10], empty}`; фон модели — точный clear-цвет превью (вынесен в `GeometryPreview::kClearColor`), фон референса — мажоритарный RGB 4 углов (поле `reference_background` в ответе); `rows` — средняя доля ширины силуэта в полосе. CPU-ядро — `FrameCompare.{h,cpp}`, смоук на синтетике (точные changedPct/bbox/rows, края порога 8/9, тай углов, размеры side-by-side); headless — обе команды отвечают `no_frame_loop` до разбора аргументов (пин в RPC-смоуке). Живая приёмка (Release, village_house `house`): первый compare → `no previous frame`, повтор → `changed_pct: 0.0` (детерминированный рендер), `params{width:10}` → 26.96 % с bbox `[413,152,1622,1042]` внутри кадра 1982×1042, magenta-маска ровно на доме; `reference` с синтетическим силуэтом дома → ref_1.png 3028×1042, метрики референса сошлись с генератором точно (w_over_h 0.7508 = 240/320). MCP: `pgg_render(compare=...)`, новый `pgg_reference`; контракт — `docs/pgg/viewer_rpc.md`. Пропорции снимались по пикселям референса руками, а «стало ли лучше после правки» — глазами по двум PNG. (а) `pgg_render{compare=prev}` — вместе с кадром отдавать diff-метрики с предыдущим кадром того же узла/камеры (доля изменившихся пикселей, bbox изменений в пикселях, PNG-разница с подсветкой) — дешёвый ответ на «правка вообще попала туда, куда я целился». (б) `pgg_reference{image, node, ortho=front}` — положить референс рядом с орто-кадром одного размера (side-by-side PNG) и вывести силуэтные метрики: bbox силуэта модели vs референса в долях кадра, отношение высот/ширин по горизонтальным срезам — числа, по которым агент сверяет пропорции без ручного счёта пикселей. Это дополняет C2 (структурный diff геометрии) визуальной стороной.
- **F4. Автоперечитывание файла.** **Статус: реализовано (2026-09-09).** Уточнения по ходу — фактология «что было stale» (проверено живым экспериментом на Release-вьювере до реализации): сами прогоны (`render`/`probe`/`export`) и раньше читали диск свежо — `pgg::runFile` перечитывает и перепарсивает файл с импортами на каждый вызов (`engine.cpp`), правка `radius` в файле без `load` меняла bbox следующего `render` — «render рисует старое» из сессии относилось не к данным прогона. Реально устаревали: (а) **запиненные на load значения параметров** — дефолт param'а снимается в `g_paramValues` при `loadFile` и передаётся в каждый прогон как явное значение, поэтому правка ДЕФОЛТА в файле без `load` была невидима (эксперимент: смена `param seed` 42→7 не меняла `rock:stats`), как и добавление/удаление param'ов; (б) **состояние вьювера** — граф нод, панель диагностик, набор param'ов в `status`. Реализация: `g_fileMtimes` (canonical путь главного файла + `ModuleClosure.modules[].canonicalPath`, mtime через `std::filesystem::last_write_time` в нс int64 — сравнение на равенство), проверка перед `render`/`probe`/`export`; изменение → `loadFile(g_filePath)` + в ответе `reloaded:true` и `load_diagnostics:[...]` (пустой массив при чистой загрузке; без изменений — `reloaded:false`, поле `load_diagnostics` отсутствует — зафиксировано так); ошибки загрузки (парс/импорты) → `ok:false, kind:"run_errors"` со списком диагностик в message БЕЗ прогона (конверт как у рантаймовых ошибок render, b3383a1 — битый файл не рисует половину сцены); `load{source}` не отслеживается (temp-файл `tmp/pgg_rpc_source/src_N.pgg` снаружи не правится — флаг `g_mainFileFromRpcSource`). Побочное поведение: авто-reload сбрасывает выставленные через `params` значения в дефолты файла — ровно как явный `load`. Живая приёмка: правка tmp-копии `lamp_fence.pgg` без `pgg_load` отразилась в следующем `render` (`reloaded:true`, bbox ymax 3.97→4.47), правка импорта tmp-копии `lib/ironwork.pgg` — тоже (`fence` ymax 1.4835→1.8435); битая правка → `run_errors` без кадра (PNG не пишется). После правки `.pgg` нужен явный `pgg_load`, иначе `render` рисует старое; агент это забывает. Сервер запоминает mtime загруженного файла и его импортов (модули из `lib/` тоже правятся); `render`/`probe` при изменении сами делают перезагрузку и включают её диагностики в ответ; `has_errors` при этом — ошибка `run_errors`, как для прогона. Явный `pgg_load` остаётся для `source` и смены файла.
- **F5. Статическая схема сквозь def-источник `realize`.** **Статус: реализовано (2026-09-09).** Уточнения по ходу — фактология «почему схема была открыта» (проверена экспериментом до правки): механизм `instanceSource` уже существовал и работал — схема выхода def'а доезжает до `instance_on_points` через `_lift`-binding'и экспансии (контроль: def с литеральным `mark(..., "iron", ...)` в источнике ловил E609 статически ещё до правки). Обрыв был раньше по цепочке: def'ы уровня `parts.piece(size, pos, grp)` делают `mark(placed, grp, ...)` с именем группы из string-параметра, а `literalString` считал любой определённый ident «вычисленным, недоказуемым» — хотя в плоской программе параметр материализуется binding'ом `piece[0].grp = "iron"` с литералом вызывающего. Дальше домино: `mark` открывал схему → `mergeSchemas` при open-операнде отдавал open → выход def'а открыт → `instance_on_points` видел `source.open` → `instanceSource` не ставился → `realize` открыт → `@tint` на points после realize статически невидим → конфликт всплывал только в рантайме. Реализация (~60 строк в typecheck.cpp): константно-строковая провенанса `constStrings_` (плоское имя → доказанная строка, собирается в `indexStmt` в порядке файла; цепочки идентов резолвятся — def, передающий свой string-параметр ниже по вызову, тоже остаётся закрытым) + резолюция через неё в Ident-ветке `literalString`; схема выхода def'а закрывается, и существующий `instanceSource` проносит её в `realize` — E609 ловится статически на `load`/`check` (репро с настоящими `lib/` — 0.15 с wall-clock вместе с запуском процесса). Заодно причесано статическое зеркало merge: `mergeSchemas` сообщает доменный конфликт одного имени один раз на шаг свёртки (как runtime), а не по разу на каждый домен левой стороны — на репро инцидента это 2 диагностики вместо 3 одинаковых. Имена, не доказуемые константными (launch-param, вычисленные выражения), по-прежнему открывают схему и откладывают E609 в рантайм (запинено тестом). Согласованное изменение инструмента: `PggTool check` был только parse+lint и статических ошибок не видел вообще — теперь гоняет префикс `pgg::run` (closure → `expandProgram` → `typecheckFlat`, без `Engine::run`, как `load` вьювера из A1); E604 в check подавлен (все объявленные param'ы считаются привязанными — у check нет запуска), поэтому check впервые отвечает ошибкой на файлах, которые и так не запускаются на этапе E5 (`corpus/messy*.pgg` — E201 версионирования импорта, модули `resources/pgg/cottage/*` standalone — E501 без import roots; оба вердикта совпадают с `run`). Тесты: `Schema.StaticE609ThroughDefInstanceSource` (репро уровня инцидента — def-источник с param-именем + `set @tint domain=faces` у соседа, статическая E609, outputs пусты), `Schema.DefInstanceSourceMatchingDomainIsClean` (контроль против пересрабатывания), `Schema.UnprovableSourceNameStillDefersE609ToRuntime` (фолбэк); смоук RPC-блок — `load{source}` с репро отвечает E609 в `diagnostics` с бюджетом `ms`. Корень инцидента с E609: `instance_on_points(pts, source = picket(...))` с def-вызовом в `source` оставляет схему инстансов открытой, и `@tint` на points после `realize` статически не виден — конфликт с `@tint` на faces соседа всплыл только в рантайме. Схема выхода def'а известна после его typecheck — прокинуть её в `instanceSource`, чтобы E609 ловился на `load` за миллисекунды, а не после прогона. Тест — репро из сессии (`stone_pier` с `domain = faces` + `picket_fence`).

**Приёмка F:** кадр `pgg_render` по умолчанию содержит только превью, модель при `fit=all` занимает ≥ 60 % большей стороны кадра; `orbit[2]`/`zoom` описаны в схеме инструмента; `compare=prev` на правке цвета одной группы даёт bbox изменений внутри bbox этой группы; правка `lib/ironwork.pgg` без `pgg_load` отражается в следующем `render`; репро E609 из `lamp_fence` — ошибка на `pgg_load`.

## 6. Что не делаем

- REPL/интерактив: агент работает вызовами — нужны идемпотентные команды с полным ответом, не сессия команд (сервер держит **состояние**, но каждая команда самодостаточна).
- Графический дебаггер узлов в PggViewer — вью для человека.
- Свой формат вместо OBJ — нужны расширения экспорта (группы, цвета), не замена.
- Offscreen FBO-рендер ради скриншотов — не нужен, readback с swapchain уже есть на всех бэкендах; чистый кадр превью (F1) — кроп readback'а и скрытие UI на кадр, не отдельный рендер-таргет.
