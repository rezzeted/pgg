# PGG — заметки по реализации (для агентов и людей)

Внутренняя кухня языка PGG: что реализовано по этапам, где какой файл, инженерные грабли и инструменты.
Это **не** спецификация языка — она в `docs/pgg/geometry_generation_language.md` (единственный источник правды по семантике; ссылки на § ниже — туда).
Файл вынесен из `AGENTS.md`, чтобы корневые инструкции не раздувались; правила работы с репозиторием (сборка, тесты, стиль) — по-прежнему в `AGENTS.md`.

`docs/pgg/geometry_generation_language.md` — ТЗ языка PGG (текст-first нодовый граф для LLM-агентов + нодовая проекция для человека); этапы и критерии — §15 там. Реализованы этапы **E0** (парсер + форматтер + линт), **E1** (CPU-ядро исполнения: источники §8.1, трансформации §8.2, поля §8.5, выражения §6.3, memoization полей §4.4), **E2** (группы §8.6, атрибуты §8.7, разброс/инстансы §8.8, агрегаторы §8.10, `merge` из §8.3), **E3** (воспроизводимость и кэш §5.2–5.3: финальный RNG-контракт + golden-векторы, numeric profile, пул потоков + параллельные per-element циклы, структурные фингерпринты + межпрогонный LRU-кэш), **E4** (SDF §8.4: первоклассный тип `sdf` — иммутабельное аналитическое дерево, оба критерия §15 — скала в SDF-конвейере и стена из экземпляров одной формы, корпус `e4_sdf_rock.pgg`) и **E5** (композиция §7 целиком — def, импорты, контракты, param/output: полная статическая экспансия def-вызовов в плоский граф, статический вывод схемы, корпус `tower.pgg` теперь исполняемый эталон §16) и **E6** (отладка §9: пробники-инспекторы L0–L2, tap, `--probe`/`--debug`, instance path, aggregate-режим) и **E7** (зоны §5.4 — repeat/foreach с `@iteration`/`@piece_index`, fracture §8.11 (SDF-Вороной v0), islands §8.3, линт W004/W005 §6.5; корпус-эталоны `e7_repeat_settle.pgg` и `e7_fracture.pgg`) и **E8** (нодовая проекция §10 read-only: граф выводится из текста, layout-hints в комментариях переживают машинные правки, проваливание в def по instance path — viewer PggViewer).

- `src/libs/pgg` — desktop-only (на emscripten CMakeLists возвращается: wasm-поставка — вьювер с запечённой геометрией, спека §13.1). Парсер — **ANTLR4 4.13.2** (vcpkg-порт `antlr4`, конфиг `antlr4-runtime`, таргет `antlr4_static`); грамматика — `grammar/Pgg.g4`, сгенерированные файлы коммитятся в `parser_gen/` (**не редактировать руками**). Сборка AST — грамматический композитор `src/compositor.*` (спека §13.2): actions в `.g4` — только однострочные триггеры `gc`; конструкции фиксированной арности идут через `returns` + метки, открытые тела (def/зоны/файл) — кадрами `gc.beginX/endX`. Диагностика — E1xx со спанами (свой error listener вместо дефолтных сообщений ANTLR, спека §11); validator-lite: E102 (SSA, с исключением портов состояния зон §5.4), E103 (forward-ref), W001 (unused), неизвестные имена типов. Форматтер — канон §6.4 (комментарии из hidden channel сохраняются; kw-args в объявленном порядке — только для def того же файла).
- `src/libs/pgg/src/eval/` — ядро исполнения **E1+E2+E3+E4+E5+E6+E7**: иммутабельная `Geo` с structural sharing по колонкам (§12.1), counter-based `rng` на pcg3d (алгоритм — финальный контракт языка с §19 v1.0; golden-векторы запинены в `repro_test.cpp`), компилятор выражений в `FieldNode`-DAG с мемоизацией по ключу (поле, геометрия, домен) и счётчиками вычислений для тестов, единый реестр сигнатур builtin'ов (источники/трансформации/генераторы полей/функции выражений — им движутся и typecheck, и компилятор, и диспетчер), статический typecheck (E201–E206, E604, E605, запрет `field<T>`/`rng` в `output` §6.7; multi-output деструктуризация для узлов с `results` в сигнатуре), pull-драйвер с ленивостью N2. Публичный API — `pgg::run(...)` в `include/pgg/eval.h` (RunResult: outputs/diagnostics/probes/stats). Отложенные узлы (`import_mesh`, §8.3 кроме merge/islands, raycast/transfer) дают чистую ошибку «не поддержано на этапе E5», не падение. Грабли: bare ident в named-аргументе enum-параметра — type-driven литерал (как в E0-валидаторе); vec-литерал `(…)` — знаковые числовые константы, минимум 2 компоненты (§19 v1.9; `(-1)` — скаляр в скобках, не vec1); swizzle в выражениях нет, идиома — `dot(@N, (0, 1, 0))`; многострочных вызовов в грамматике нет (оператор = строка), списочный литерал пишется в одну строку.
- **E2 по файлам:** группы — отдельное per-domain хранилище на `Geo` (`GroupSet`, не атрибуты: E305 ≠ E302), `mark`/`unmark` + `ingroup` (междоменное чтение — интерполяция с порогом > 0.5); атрибуты — **typeinfo v1.14** (`AttrColumn::typeInfo ∈ {none, vector, normal, point, quaternion}`, спека §4.3: `set(..., typeinfo = auto)` выводит только однозначное — зарезервированные имена (`N`/`orient`/`tint`/`color`/`Cd`) и не-векторные типы; **vec3/vec4 под свободным именем без явного тега — E610** (v1.15, статика + рантайм; туда же тег не по типу значения и стампы `orient`/`tint`/`scale`/`variant` не своего типа); `transform`/`realize` двигают колонки по тегу через общий `transformColumn` (geometry.cpp), `merge` требует равный тег (E609) и заполняет односторонние имена нейтралью по тегу (`neutralColumnLike`: identity-кватернион / производные нормали / ноль), `realize` проверяет варианты тем же правилом E609 (`checkRealizeContracts`: домены + тег) и `@variant` вне списка — E611 (clamp снят), `transform` с неравномерным масштабом на `geo<instances>` — E611; тег едет через promote/rename/distribute/fracture и входит в фингерпринт; статическая схема — `SchemaAttrType {type, info}` + флаг `nStale` (W006: чтение сохранённого `@N` после `set_position`/`smooth` без `compute_normals`; `remove_attr(g,"N")` снимает и `Geo::normals`); производный `@N` — `derivedNormals` в `sampleNormals` при отсутствии колонки (только меши с гранями); грабля: `typeinfo = none` парсится none-литералом — `literalString` и `opSet` читают его как "none"), `set` (домен из поля: константа → detail, иначе points; явный `domain = auto/points/corners/faces/detail` побеждает вывод — merge-безопасная идиома для по-точечных констант, v1.12; имя глобально — запись стирает одноимённые колонки с остальных доменов, last-write-wins, иначе устаревшая копия теневала бы новую на пути чтения points→…→detail; v1.11), `remove_attr`/`rename_attr`/`promote`, молчаливая интерполяция §4.3 одной функцией `sampleAttrColumn` (`geometry.cpp`, `@P`/`@N` тоже читаются на любом домене через неё); разброс — `distribute_points` детерминированной приоритетной схемой v0 (per-face кандидаты `ceil(area·dMax·4)` адресом `(rng, face_id, attempt)`, плотность полем на probe-геометрии с барицентрическим наследованием, poisson min_dist — highest-priority-wins по spatial hash, rate не гарантирован, см. §19 v0.9); инстансы — `GeoKind::Instances` + shared `instanceSources` (10⁵ без realize бесплатно), `realize` материализует `@tint` в point-attr и переносит все домены источника (points/corners/faces attrs+groups union-схемой, corner-`N` поворачивается стампом, detail — первого варианта; до v1.13 переносился только points — face-группы материалов терялись при инстансинге), `transform` на `geo<instances>` компонует `@orient`/`@scale` (материализует оба) и поворачивает corner-`N` у мешей; агрегаторы — `bbox` (первый multi-output, `mn, mx = bbox(g)`), редукции строго по `@index`, пустая выборка — E601 (count/sum → 0); `merge<K>` — конкатенация mesh/points с union-семантикой колонок (zero-fill, detail — левый операнд, instances-merge — ошибка этапа) **+ правило E609 (v1.12): имя, присутствующее в обоих операндах, обязано жить на одном наборе доменов, а detail-значения — совпадать, иначе ошибка** (грабля: merge якорей с константными orient'ами раньше молча схлопывал их в значение первого — клинья бандажа stone_arch вылезали из кладки; статическое зеркало на закрытых схемах, typecheck). Реализации: `builtins_attrs.cpp` (§8.6+§8.7), `builtins_scatter.cpp` (§8.8 + merge), `builtins_aggregate.cpp` (§8.10). Грамматика дополнена списочным литералом `[a, b]` (значение `T[]`, только value-уровень).
- **E3 по файлам:** `profile.h/.cpp` — numeric profile (строка из compile-time фактов: pgg ABI 3, версии RNG/noise 1/1, компилятор, ISA, FP-флаги → `profileId` = fnv1a64; seed всех фингерпринтов, в `RunStats` и выводе PggTool). `fingerprint.h/.cpp` — структурный фингерпринт binding'а за O(AST) без вычислений (`mix(profileId, expr-структура, fp(зависимостей))` с мемо по имени; launch-параметры — по привязанному значению/дефолтному литералу; 0 = uncacheable); `fingerprintValue` хэшит payload (float по бит-паттерну, geo по контенту с сортированными именами колонок). `parallel.h/.cpp` — пул `std::thread` (lazy singleton = hardware_concurrency) + `parallelFor(count, threads, fn)` чанками с разъединённой записью, порог 4096 (< — inline), анти-вложенность thread_local'ом (воркер **и** вызывающий поток на время диспатча — грабля: caller участвует в drain, без пометки вложенный вызов рекурсивно входил в пул с одним outstanding job → дедлок). `cache.h/.cpp` — `MemoryCache`: LRU поверх `unordered_map<fp, TypedValue>` (ёмкость конфигурируется, дефолт 512, mutex), указателем в `RunParams::cache` (nullptr = выкл; кэш инспекторов E6 — отдельный инстанс по дизайну). Проводка — `evalBinding`: fp → lookup (hit → тот же fan-out tuple) → miss: evaluate + store (только value-binding'и: geo/скаляры/строки/списки; field/rng не кэшируются). `RunParams += threads` (0 = hardware, 1 = последовательно — бит-в-бит то же), `RunStats += cacheHits/cacheMisses/threadsUsed/profileId`. Параллельно: evalField element-loop (ядра + §6.3 + §8.5), `realize` (по якорям, precomputed-срезы), `compute_normals` (per-face → per-point gather по incident-спискам, порядок суммы по точке бит-в-бит прежний), `distance_to` (per-query), `distribute_points` (кандидаты per-face по смещениям, probe/thinning/poisson по кандидатам read-only hash); последовательно: редукции агрегаторов (@index), мемо полей, построение hash и компактификация в Пуассоне, конверсии буферов, merge, smooth/transform. **Семантика poisson уточнена (§19 v1.0):** принят ⇔ нет thinning-принятого со строго большим приоритетом (ничья — по индексу) в радиусе — единственное конфликт-free множество вместо жадного; golden'ы e2 переписаны (25 → 15 якорей, расклад 10/15 → 4/11).
- **E4 по файлам:** `sdf.h/.cpp` + `builtins_sdf.cpp` — первоклассный `sdf` как иммутабельный аналитический `SdfNode`-DAG (sphere/box/CSG/grind/displace/instance/Grid): `eval` — чистая рекурсия (thread-safe, из параллельных сэмплингов), `conservativeBBox` с двойным инвариантом (содержит iso-0 + cull-safe снаружи: intersect → bbox(a), не пересечение боксов); `Value` получает `SdfPtr` **в конец variant'а** (index 12, индексы 0..11 неподвижны). `sdf_displace` глубоко копирует FieldNode-DAG в собственную арену (payload самодостаточен для MemoryCache) и валидирует контекст сэмпла одним проходом: `@N`/`@index`/`@<атрибут>`/`distance_to`/`ingroup` → **E307** (recovery — ребёнок без изменений); точечный `evalFieldAtPoint` зеркалит буферные формулы (§6.3 через `evalExprFuncBuf` на 1-элементных буферах, fbm/vnoise/random* — прямые скалярные вызовы с той же раскладкой). `sdf_instance_on_points` — трансформ зеркально `realizeInstances` (`p_local = q⁻¹(p−P)/s`, `d·s`; якоря со scale ≤ 0 отбрасываются), точное отсечение по worldAABB якоря (`dist ≥ cur+k` → пропуск бит-в-бит, есть тест). `sdf_from_mesh` — детерминированный AABB-BVH (`MeshBvh`, mid-split по длиннейшей оси, приоритет (dist,face,tri)) + псевдо-знак по нормали ближайшего треугольника → Grid-узел (трилинейный сэмпл; `distance_to` НЕ рефакторился — миграция на BVH позже). `mesh_from_sdf` — marching cubes: стандартная 256-таблица Bourke/Bloyd (`mc_tables.h`, атрибуция; face-consistency доказана исчерпывающей проверкой 256×6 — asymptotic decider не нужен; опубликованные строки ориентированы изнутри солида — при эмиссии разворачиваются), дедуп вершин по ключу ребра грида, страж `|vb−va|<eps → 0.5`, bbox = conservativeBBox + 1 воксель, ось > 4096 → **E306**, воксель пограничной плиты ≤ iso → **W002**; выход — только `@P` (атрибутный барьер §8.4). Формулы примитивов/smin/smax и политика margin (решётка 4³, ×1.3) — контракт §19 v1.2; края: `k ≤ 0` → жёсткая операция, `+inf` — нейтральный элемент smin (поле пустого instance'а). Кэш: `cacheableValue(sdf) = true`, `fingerprintValue(sdf) = false`; параллельны только сэмплинги гридов (N7), эмиссия и BVH-build последовательны. Тесты — `sdf_test.cpp` (27), корпус-эталон `src/tests/pgg/corpus/e4_sdf_rock.pgg` (оба критерия §15 E4 + `output rock_field` сырым sdf).
- **E5 по файлам:** `modules.h/.cpp` — замыкание импортов (`import lib.noise` → `<root>/lib/noise.pgg` по `RunParams::importRoots` по порядку; `runFile` добавляет каталог файла неявным root'ом): E501 (не найден; без roots — hint про importRoots), E502 (цикл, с цепочкой), E506 (библиотечный def без docstring), namespace vs builtin → E102 (остальные конфликты namespace — E0-валидатор), версионирование `@1.2` — ошибка этапа; модуль парсится раз (кэш по canonical path; `ModuleInfo` живёт в `ModuleClosure::ownedModules` — грабля: указатели в namespaces/defs ссылаются на владельца), его E0-диагностики копируются с префиксом пути; из модуля видны только top-level def'ы, E604/E605 к модулям не применяются. `expand.h/.cpp` — **полная статическая экспансия**: def-вызовы инлайнятся в плоский граф до typecheck/fingerprint/engine (файл без def/import проходит бит-в-бит как раньше — возвращается исходный `File*`); инстанс `foo[k]` (счётчик по unqualified имени def, не по указателю: обёртка `def brick_courses` вокруг `plan.brick_courses` не должна оба стать `brick_courses[0]` — иначе `ch = ch` самоссылается и evalBinding переполняет стек), локали → `foo[k].local`, параметры → binding'и `foo[k].param = <arg вызывающего>` (arg-выражения НЕ переименовываются), вызов внутри выражения — лифт в `_lift<N>`, statement-вызовы связывают цели напрямую с выходами инстанса; до экспансии — проверки графа def'ов: E503 (рекурсия, DFS с цепочкой; при цикле экспансия не запускается) и **E401 статически** (стохастичность транзитивно по DAG вызовов; `rng_from_seed` внутри def — источник энтропии); E505 (неизвестный qualified symbol), E202/E203 binder по образцу `bindCallArgs`. `schema.h/.cpp` + typecheck — статический вывод схемы слит с typecheck в один topo-проход по flat-графу: закрытая схема (kind/@N/attrs/groups per domain) по transfer-таблице (источники, set/remove/rename/promote/mark, merge, distribute_points, instance/realize, **mesh_from_sdf — барьер {@P}**); поля, потребляемые узлами на закрытой схеме, проверяют @attr/@N/ingroup ⊆ схемы → E302/E305 static («(static schema)» в сообщении; closure поля — транзитивно через локальные field-binding'и, поэтому границы def прозрачны, дословный пример §7.2 с `@height_rel` ловится до запуска); открытая схема (не-литеральное имя и т.п.) → runtime-фолбэк без изменений. Declared-типы интерфейса def — E204 на binding'ах параметров/выходов (recovery — объявленный тип). Контракты: attr-form статически против схемы (E303/E304 до запуска) или runtime-колонкой на открытой, условия — литеральные статически, остальные runtime (engine считает expects при первом pull'е выходов инстанса, ensures — после; раз на инстанс); текст автора + ` [instance <path>]` (базовый §9.5; runtime-ошибки внутри инстансов тоже суффиксируются путём). `RunParams += importRoots`; герметичность E105 — в E0-валидаторе (тело def не захватывает top-level param/rng/binding файла, ловится `PggTool check`). Фикстуры модулей для тестов — `src/tests/pgg/corpus/lib/`. W003 (один rng → 2+ стохастика, §6.5) реализован (A1, спека v1.8): покрывает только builtin-стохастику (`kStochasticOps`, тот же список, что у W004/W005), def-вызовы — вне скоупа (идиома §7.3 запинена `Def.SameRngReproducesSameResult`); идентичность генератора — структурный ключ `resolveRngKey` по SSA-алиасам (rng_from_seed → call-узел; split_rng с константным ключом → (родитель, текст ключа), с неконстантным → call-узел; alias_rng — exempt на любой глубине цепочки; def-параметры — по имени с пространством per def), одно предупреждение на ключ на спане второго потребителя; тесты — `validate_test.cpp` (11 сценариев + корпус-барьер).
- **E6 по файлам:** `probe.h/.cpp` + проводка в `engine.cpp` — подсистема отладки §9: пробник = дополнительный ленивый корень pull'а (инспектор — чистая функция над уже вычисленным значением binding'а, делит env и кэш прогона; пробник на середину графа не вычисляет хвост — доказано счётчиками). Спека `path:inspector[param=value,...]` (`schema`/`stats`/`coverage`/`table`, дефолт schema+stats; params `limit=N`, `aggregate=stats`), разрешение путей по метаданным FlatProgram (flat binding → instance path → безындексный def → geo+attr/group терминал с sugar `make_rock[1].disp`; binding выигрывает у sugar), форматы детерминированы (сортированные имена, `%g`, f64 mean по @index, nearest-rank p50/p90, записи `probe|tap <path>: <text>`). Теперь начало сдвинуто на иррациональную долю вокселя (`kLatticePhase` = 0.381966, сопряжённое золотое сечение): ни одна грань в рациональной координате модели не совпадает с плоскостью решётки; фича тоньше вокселя, не пересекающая плоскость решётки, стабильно **пропадает целиком**, а не рвётся. Второе: вершины рёбер, попавшие в один узел (значение ровно iso → t = 0/1), свариваются по битовому равенству позиции, индекс-вырожденные треугольники отбрасываются, неиспользуемые точки компактятся — раньше в оболочке крыши 12 % треугольников были нулевой площади. Два уточнения (2026-09-09): (а) дальний конец ребра считается той же решёточной формулой `mn + ivec3 · voxel`, что и ближний — `pa + voxel` давал битово другой float для того же узла, сварка его не видела, и по оболочке оставались открытые рёбра (`check` на репрокейсе: boundary 3722 → 0); (б) `t` в пределах `kSnap = 1e-6` от 0/1 (значение в узле равно iso с точностью до округления float) снапится на узел — иначе вершина в нанометре от узла не сваривается и треугольник живёт иглой (~1 % граней). Порог намеренно на уровне округления, не геометрический: сварка — это edge collapse, при агрессивном пороге (1e-4) на `e7_fracture` появлялось non-manifold ребро; оставшиеся тонкие треугольники (`needles` в `check`, t ~ 1e-5) топологически безвредны и не считаются дефектом. - **Грабли ANTLR C++:** в actions контекст правила — `_localctx` (не `ctx`); `returns`/`locals` не переваривают запятые в template-типах — нужны алиасы (`pgg::DefParamList` и т.п. в `ast.h`); семантические значения — сырые указатели в арену gc (без `unique_ptr` в `returns`).
