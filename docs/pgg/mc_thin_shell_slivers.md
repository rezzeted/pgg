# MC-плавни на тонкой оболочке пересекающихся SDF-призм — расследование

**Статус: закрыто (2026-09-07, спека v1.24.2).** Корень найден и исправлен в ядре (`sdf.cpp`, `meshFromSdfExtract`), регрессионный тест `MeshFromSdf.SubVoxelWallIsNotATornSheet`. Обход `269b9e0` (+0.04 у торцов щипца) оставлен как безвредный, но больше не нужен — `cottage_mansard` без него рендерится чисто. Ниже — итог, затем исходный бриф как история.

## Итог расследования

**Гипотеза брифа («совпадающие плоскости CSG») не подтвердилась** — совпадение плоскостей было корреляцией, а не причиной. Реальный корень — два независимых факта:

1. **Торцы у `gable_prism`-оболочек — стенки толщиной 1 см (0.2 вокселя).** `inner` строится как `w − 0.02`, поэтому между внешним и внутренним торцом остаётся 1 см материала — это и есть «стенка», которую MC на шаге 0.05 представить не может. Поле при этом корректно (проверено: все вершины меша репрокейса лежат на нулевой изоповерхности с точностью 5 мм, отрицательная область на плоскости торца — ровно треугольник щипца).

2. **Грань примитива лежала ровно на узлах решётки.** Начало решётки было `bbox − voxel`, а conservative bbox осевого бокса — это его грань. Значит грань бокса (и любая грань в целом числе вокселей от неё — например внутренний торец на 1 см = 0.2 вокселя дальше *не* попадает, но внешний попадает; на другом торце наоборот) ложится точно на плоскость выборки, где поле равно 0 с точностью до округления float. `v < iso` тогда переключается шумом округления, и на 1-см стенке, чья единственная «внутренняя» плоскость выборки — это её же грань, MC даёт лист, рваный на полосы: **та самая бахрома**. Подтверждено по OBJ репрокейса: вершины листа при `z = +3.43` лежат ровно на `z = 3.42` (внутренний торец = узел), при `z = −3.43` — ровно на `−3.43` (внешний торец = узел); фаза по x: узлы на `±2.93`/`2.92` — грани главной призмы. Асимметрия «только один торец» из брифа — ровно это.

**Фикс (`sdf.cpp`):**
- начало решётки сдвинуто на иррациональную долю вокселя: `mn = bbox − voxel · (1 + 0.381966)` (сопряжённое золотое сечение) — грань в любой рациональной координате модели не совпадает с плоскостью решётки. Следствие: фича тоньше вокселя, не пересекающая плоскость решётки, теперь **стабильно пропадает целиком**, а не рвётся (1-см торцы репрокейса исчезли на обоих концах; в старой версии один торец был «полным листом», другой — бахромой);
- вершины рёбер, попавшие в один узел (значение ровно iso → t = 0/1), свариваются по битовому равенству позиции; индекс-вырожденные треугольники не эмитятся, точки без граней компактятся. В оболочке крыши репрокейса таких треугольников было 15 тыс. из 154 тыс. (12 %); на сфере/боксе — 0–6. Сварка нужна именно по позиции: простой дроп по совпадению позиций при разных индексах открывал рёбра (в `tower` появлялись 6 non-manifold рёбер).

**Цена:** позиции всех SDF-мешей сдвинулись на доли вокселя — пересняты голдены `sphere`/`rock`/`wall`/`fracture`/`tower` (bbox сферы теперь с допуском 1e-3: полюса между узлами, линейная интерполяция кривого поля недотягивает на `voxel²/2r`). Битовой идентичности SDF-мешей до/после нет.

**Правило для авторов (спека §8.4):** стенки оболочек ≥ 2·voxel, либо делать оболочку открытой (внутренний объём *длиннее* внешнего), а не «на 0.02 короче» — 1-см торцы `gable_prism` были мусором, который раньше случайно то рисовался, то нет.

## Исходный бриф (история)

## Симптом

В мансардном варианте коттеджа (`resources/pgg/cottage_mansard.pgg`, крыша `roof.multi_gable` из `resources/pgg/cottage/roof.pgg`) на торце поперечного щипца из-под ветровой доски свисала «бахрома» — 10–15 тонких вертикальных пластин ~0.12 шириной и до ~1.2 м высотой, идущих вдоль косача торца. Видна только под некоторыми углами (торец заподлицо смотрит на камеру, `yaw ≈ 255°`), на одном торце из двух.

## Факты (установлено бисектом, 2026-09-07)

- Бахрома принадлежит группе faces `roof` — это **SDF-настил** (`deck` = `sdf_subtract(sdf_union(main_outer, wing_outer), sdf_union(main_inner, wing_inner))` → `mesh_from_sdf(voxel = 0.05)`), а не черепица/крышки резов (под highlight `faces:tile`/`faces:cut` не светилась, под `faces:roof` светилась).
- Замеры по OBJ (`PggTool run ... --obj`, питон-скан граней): плавни — вертикальные пластины ~0.3×0.3 в плоскости торца щипца (мир x = ±3.43), высота по косачу (y растёт 4.85 → 7.73 с приближением z к 0).
- Геометрия симметрична относительно x = 0, но артефакт был только на торце −X: фаза воксельного грида (берётся из conservative bbox поля, асимметричного) решает, где вылезает бахрома.
- Оболочка тонкая: 0.12 / воксель 0.05 = 2.4 вокселя.
- **Ключевое условие:** торцевая плоскость призмы щипца (`wing_*`, торец z = ±3.43) совпадала с плоскостью карниза главной призмы (`main_*`, край z = ±3.43). На совпадающих плоскостях поле имеет излом ровно по границе тонкой рамки торца.
- **Обход (в main):** торцы призм щипца сдвинуты на +0.04 наружу (`w = wl + 0.04` / `wl + 0.02` у inner) — совпадения плоскостей нет, бахрома исчезла целиком, меш полегчал на ~800 точек. Грабля записана в `implementation.md` (параграф про `roof.multi_gable`).

## Минимальный репрокейс (подтверждён — бахрома на обоих торцах)

Файл (положить в `resources/pgg/_probe_mcbug.pgg` — вьюверу нужны импорты `lib.*`, `--lib` у PggViewer нет; в PggTool можно из любого места с `--lib resources/pgg`):

```
import lib.shapes

outer = sdf_union(shapes.gable_prism(ridge_y = 3.43, drop = 0.0, w = 5.86, d = 5.0, floor_y = 0.0), shapes.gable_prism_z(ridge_y = 2.93, drop = 0.0, w = 6.86, d = 5.86, floor_y = 0.0))
inner = sdf_union(shapes.gable_prism(ridge_y = 3.43, drop = 0.12, w = 5.84, d = 4.98, floor_y = 0.0 - 0.5), shapes.gable_prism_z(ridge_y = 2.93, drop = 0.12, w = 6.84, d = 5.84, floor_y = 0.0 - 0.5))
shell = sdf_subtract(outer, inner)
mesh = compute_normals(mesh_from_sdf(shell, voxel = 0.05), mode = auto, angle = 35)
output mesh
```

Смотреть снизу-сбоку на торцевые треугольники оболочки:

```
caffeinate -u -t 5; _int_clion/src/apps/PggViewer/Debug/PggViewer resources/pgg/_probe_mcbug.pgg --preview=mesh --preview-orbit=245,-25,0.9 --shot=/tmp/mcbug.png
```

Ожидаемая картина: по нижней кромке/косачам торцевых рамок висят вертикальные плавни-полосы. Контроль (без совпадающих плоскостей): `w = 6.86 → 6.90` у внешней `gable_prism_z` и `6.84 → 6.88` у внутренней — плавни исчезают.

Диагностика по биндингам: `_int_clion/src/apps/PggTool/Debug/PggTool run <file> --lib resources/pgg --probe '<binding>:table[limit=200]'` дампит @P по точкам; `--obj <dir>` — OBJ с цветами (`v x y z r g b`).

## Куда смотреть в движке

- `src/libs/pgg/src/eval/sdf.cpp` — `meshFromSdfExtract` (≈ line 609): грид = conservative bbox поля ± 1 воксель; далее классический MC с линейной интерполяцией по рёбрам, дедуп вершин по ключу грид-ребра, последовательная эмиссия в порядке (z,y,x) (детерминировано, потоки влияют только на сэмплинг поля). Там же `SdfNode::eval`/`conservativeBBox` (union = min, subtract = max(a, −b), bbox intersect = bbox(a) — отсюда порядок операндов в `gable_prism`).
- `src/libs/pgg/src/eval/mc_tables.h` — таблицы MC.
- `src/libs/pgg/src/eval/builtins_sdf.cpp` — обёртка builtin'а; комментарий про «pseudo-sign» в шапке — стоит понять, какие значения поле принимает внутри тонкой оболочки и на изломах совпадающих плоскостей.

## Гипотезы / вопросы на исследование

1. MC на оболочке толщиной 2.4 вокселя рядом с изломом поля (совпадающие плоскости union'а): интерполированные нули на рёбрах вокруг излома могут закрывать тонкую рамку паутиной пластин вместо двух раздельных стенок. Проверить: сэмплировать поле поперёк рамки (профиль значений), посмотреть ячейки, порождающие плавни.
2. Влияет ли фаза грида (сдвинуть bbox на 0.5 вокселя — симптом должен переехать/исчезнуть) — подтверждает зависимость от фазы.
3. Ожидаемое поведение: оболочка должна оставаться двумя стенками с чистой кромкой рамки. Если MC такое принципиально не держит на 2.4 вокселях — возможно нужен другой изолятор/пост-проход (surface nets — есть в бэклоге спеки §8 как `method` у `mesh_from_sdf`), либо честное предупреждение авторам (аналог W002) при оболочке тоньше N вокселей.
4. Критерий закрытия: минимальный репрокейс чист от плавней (или зафиксировано, что это врождённое ограничение MC + документировано в спеке §8.4), плюс тест в `src/tests/pgg/` (напр. корпус-файл + ассерт: нет граней-пластин вне ожидаемого объёма — по bbox против аналитических плоскостей).
