# PggServe RPC + MCP (`pgg`)

_Контракт агентского RPC (этапы A1–A3, C2, D3, E, F1–F5 из `docs/pgg/agent_tooling_plan.md`). Правя `src/apps/PggServe/`, `src/libs/pgg_preview/`, `tools/pgg_mcp/`, обновляй **этот** документ._

`PggServe [--port=9878] [--host=127.0.0.1]` поднимает TCP RPC на `127.0.0.1:9878` (построчный JSON). Реализация: `ServeRpcServer` (транспорт) + `ServeRuntime` (слоты, Engine, GPU-очередь). `poll()` не гоняет Engine: хендлер ставит работу на CPU-воркер, ответ `nullopt` + `reply` после CPU (probe/load) или после GPU (render). Занятый порт — ошибка, процесс выходит. Крошечное Sokol-окно (64×64) — только GPU-контекст, без ImGui и без графа. Linux без DISPLAY: `xvfb-run -a`.

`PggViewer` сети не слушает: десктоп-приложение со своим рендером, `--shot` / галерея остаются.

Конверт: запрос строка `{"op":"…","args":{…}}`, ответ строка `{"ok":true,"data":{…}}` | `{"ok":false,"error":{"kind","message"}}`.

## Слоты

Ключ сессии — **канонический путь `.pgg`**, не агент и не uuid. `load` создаёт или переключает слот. В ответах эхо `"session": {"file": "…"}`. `render` / `probe` / `export` / `params` / `views` / `diff` / `docs` / `reference` принимают необязательный `file` — работа по слоту, даже если другой клиент только что грузил другой файл. Без `file` — слот последнего `load` **этого TCP-клиента** (у каждого сокета свой «текущий» файл). Потолок слотов — 8 (LRU; вытесняется слот с `use_count==1`). На одном файле Engine сериализуется мьютексом слота; разные файлы — Engine параллельно, PNG по одной GPU-очереди (Sokol-поток).

`MemoryCache(4096)` — **свой экземпляр на слот**. Compare / visual baseline / diff snapshot / F4 auto-reload — per slot. Явный `load` слота сбрасывает visual/diff/sticky orbit; F4 auto-reload их сохраняет (набор param'ов всё равно перечитывается из файла, как при Reload).

Глобального `busy` нет. Клиент ждёт свой ответ. `busy` только при переполнении CPU/GPU-очереди или когда все 8 слотов заняты работой и вытеснить некого.

## Операции

- **Сессия:** `ping` → `{pong, app:"PggServe", protocol}`. `status` → `{file, params, cache, preview, profile, profile_total_ms, slots:[{file, cache, preview, last_node}], gpu, uptime_s}` (`file`/`params`/`cache` — LRU-голова).
- **Файл и параметры:** `load {path|source, lib_roots?, snapshot?}` — `source` пишется в `tmp/pgg_rpc_source/src_N.pgg` и дальше идёт как `path`; ответ — статическая проверка без прогона (closure → expand → typecheck): `{diagnostics:[{code,line,col,warning,message}], has_errors, ms, path, session}`. К `lib_roots` всегда дописывается `<repo>/resources/pgg`, если в дереве есть `lib/`. Относительный `path` сначала как есть, затем от корня репо. `params {name:value, file?}` — те же поля, что `--param` (массив → вектор `(x, y, z)`); ключ `file` слотом, не параметром; неизвестные имена — в `unknown`.
- **Прогон:** `render {node, view?, out?, orbit?, zoom?, distance?, highlight?, shading?, colors?, size?, target?, fit?, ortho?, wire?, frame?, chrome?, compare?, png?, save_baseline?, file?}` → `{path?, width, height, frame, chrome, size_clamped?, node, stats, diagnostics, camera:{center,radius,distance,target_bbox?}, render_state:{wire,chrome,ortho,target,zoom,fit}, cache, reloaded, load_diagnostics?, compare?, session}`. **Stateless (C5):** незаданный параметр берёт дефолт (`wire=false`, `ortho=off`, `target=""`, `highlight=""`, `shading=auto`, `colors=on`, `zoom=1` если нет `zoom`/`distance`/`orbit[2]`). Липкие только `orbit` (yaw/pitch) и `distance`. `view` подставляет поля из `<stem>.views.json` (явные args перекрывают). `png:false` — без записи основного PNG и без `path` (пиксели для compare всё равно снимаются). `compare` — `"prev"|"baseline"`; `save_baseline:true` или первый `compare=baseline` без слота вида создаёт visual baseline (ключ = frameKey, **на слот**); явный `load` сбрасывает его. Прогон без значения — `run_failed`; с E-диагностиками — `run_errors`. `probe {spec?, specs?, file?}` → `{records, diagnostics, has_errors, ms, cache, reloaded, load_diagnostics?, session}` — `specs:[…]` гоняет все пробники одним прогоном графа (записи в порядке specs; `spec` и `specs` складываются, хотя бы один обязателен); `export {node, obj_path, file?}`; `docs {symbol, file?}` — def слота, иначе fallback в реестр билтинов без префикса `builtin:` (успех `kind:"builtin"`; промах — `not_found` + did-you-mean); `views {file?}` → `{file, views:[…], session}`.
- **Diff прогонов (C2):** `diff {update?, file?}` — fp-level сравнение outputs слота с его снимком фингерпринтов (структурный fp `fingerprintValue`, тот же что у `PggTool run --fingerprint`/`diff`; без ΔP). Снимок: создаётся первым `diff` (`baseline_created:true`) или `load {..., snapshot:true}`; обновляется только `diff {update:true}`; сбрасывается явным `load`. Авто-reload (F4) снимок не сбрасывает. `skipped` — sdf/field без структурного fp, на `identical` не влияют.

  **Кадр render:** всегда offscreen FBO превью (`PreviewCapture` после `sg_commit()`). `chrome` и `frame=window` принимаются (агенты шлют `chrome=off`) и игнорируются. `size` задаёт размер **FBO** (дефолт 1280×720); `size_clamped:true` только при упоре в `GeometryPreview::kMaxTarget` (4096). Окно демона не кропается и не ресайзится.

  **Сравнение кадров и референс (F3):** `render {..., compare:"prev"|"baseline"}` — diff против предыдущего кадра **того же вида этого слота**. Ключ вида — узел + эффективное состояние камеры (center/radius/distance/yaw/pitch/projection/fit) + опции превью (highlight/shading/colors/wire/sdf voxels); `params` и правки файла в ключ не входят. Хранится один последний кадр на слот; `reference` его не трогает. `compare:"baseline"` — карта кадров по `frameKey` на слот. Ответ `compare`: `{available, changed_pct, change_bbox_px, diff_png}`; `available:false` с `reason` — `"no previous frame"` или `"size mismatch (prev WxH, now WxH)"`. Пиксель изменён, когда макс. разница по каналам > 8/255. `diff_png` — `tmp/pgg_rpc_shots/diff_N.png` (новый кадр ×0.3, изменённые — magenta). CPU-ядро — `src/libs/pgg_preview/FrameCompare.{h,cpp}`.

  `reference {image, node, ortho?, orbit?, zoom?, size?, file?}` — модель рядом с референсом. Ракурс детерминирован: target сбрасывается, `fit=all`, `ortho` по умолчанию `front`. Кадр FBO; `size` — размер FBO модели. `composeSideBySide` клеит `модель | разделитель 4px | референс` → `tmp/pgg_rpc_shots/ref_N.png`. Силуэт = пиксели, отличающиеся от фона > 8/255; фон модели — `GeometryPreview::kClearColor`, фон референса — мажоритарный RGB 4 углов. Ошибки: `image` не читается → `invalid_input`; без GPU → `no_gpu` (не `no_frame_loop`).

  **Камера render (A2 + C5):** `target` — `"x,y,z" | "group:<имя>" | "binding:<путь>" | "group:<grp>@<binding>"`. Неразрешённый target — `target_unresolved` (не тихий `fit=all`). Без явного `orbit` yaw ставится со стороны цели относительно центра сцены (`faceTargetFromOutside`; в орто не применяется). `fit` — `"all"|"target"` (дефолт `target`, если задан `target`). `ortho` — `"front"|"side"|"top"|"off"`. `wire` — bool. Третий компонент `orbit` и `zoom` — множитель fit-дистанции (`distance = radius·2.6·zoom`). `distance` — метры от центра орбиты, после резолва `target`, перекрывает zoom. `camera` в ответе — фактическое состояние после применения.

  **Авто-reload по mtime (F4):** перед `render`/`probe`/`export`/`diff` слот статит mtime главного файла и модулей import-closure. Изменился хоть один → `loadFromDisk(..., explicitLoad=false)` (граф и param-набор как у Reload; visual/diff/sticky orbit сохраняются), в ответ `reloaded:true` и `load_diagnostics`. Ошибки загрузки — `ok:false` `kind:"run_errors"`, прогон не выполняется. `load{source}` не отслеживается.

Грабли: `render` синхронный для клиента (CPU на воркере слота, затем GPU-очередь); `out` по умолчанию `tmp/pgg_rpc_shots/shot_N.png`. `--smoke` PggServe — CPU-only: `render` отвечает `no_gpu`. `probe`/`export` GPU не требуют. RPC-listen и `poll()` подняты до первого кадра Sokol (pump-поток в `main()`): окно демона может не стать видимым (фоновая сессия/залоченный экран, macOS) — тогда CPU-ops работают, а `render`/`reference` отвечают `no_gpu` до первого кадра. Сессионный `MemoryCache` (4096) переживает `load` того же файла: правка инвалидирует только downstream — зоны repeat/foreach кэшем пропускаются by design, поэтому тяжёлые зональные графы тёплым прогоном не ускоряются. Два host-потока могут диспатчить `pgg::parallelFor` сразу (очередь job'ов в `ThreadPool`); анти-вложенность `thread_local` сохранена.

## MCP

Один сервер `pgg` в `.mcp.json` / `.cursor/mcp.json` — Cursor стартует `python3 -m tools.pgg_mcp.launch` (на Windows без `python3` в PATH замените `command` на `python`). Код — `tools/pgg_mcp/` (`session.py` — поиск `PggServe` / автоподъём / прокси; `server.py` — FastMCP stdio). `launch` поднимает venv `tools/pgg_mcp/.venv` (python ≥ 3.10) и exec `python -m tools.pgg_mcp`. Обёртки `tools/run_pgg_mcp_server.{sh,ps1}` — только для терминала.

**PggServe поднимается автоматически:** если порт 9878 не отвечает, ищется бинарь (`PGG_SERVE`, затем Release, затем Debug по пресетам текущей ОС: linux `_int_linux_release`/`_int_linux`, macOS `_intermediate_64` + CLion `_int_clion*`, Windows `_intermediate_64/.../PggServe.exe`), `Popen([serve, "--port=…", "--host=…"])` (Linux без DISPLAY — `xvfb-run -a`; нет xvfb — `unreachable` с hint), ожидание порта до 30 с; лог — `tmp/pgg_serve.log`. Если порт уже занят старым `PggViewer --serve`, MCP к нему подключится — остановите тот процесс. Нет бинаря — MCP **не** собирает его: любой `pgg_*` отвечает `ok=false`, `error.kind=need_build` (`target:"PggServe"`, `platform`, `cwd`, `configure`/`build`/`debug_build` argv, `expected`, `candidates`, `hint`, `serve:"missing"`). Агент выполняет команды из корня репо и повторяет вызов. Живой `pgg_status` добавляет в data `serve:"running"`, `viewer:"running"` (совместимость), `binary?`, `rpc:{host,port}`.

**Пересобранный бинарь подхватывается сам:** MCP помнит mtime бинаря, с которым поднял **свой** `PggServe`. Если найденный бинарь новее и не менялся последние 2 с (линковка закончена), следующий вызов останавливает процесс, стартует новый, повторяет `load` известных слотов (по `path` + `lib_roots`, до 8; `load{source}` не повторяется) и возвращает в ответе `restarted:true`, `restart:{binary, reloaded_slots, failed_slots?}`. Чужой процесс на порту (поднят не этим MCP) не трогается: если он стартовал раньше последней сборки (по `uptime_s` из `status`), к каждому ответу добавляется `stale_binary:{binary, message}` — остановите его, MCP поднимет новый.

**Одно TCP-соединение на in-flight вызов** (не один сокет на процесс MCP). Два чата через FastMCP иначе смешают JSON на одном сокете. Python-сессия помнит `last_file` последнего успешного `load` и подставляет его как fallback `file=`; два чата на одном MCP могут гонять этот fallback — **передавайте `file=`**, если в этом ходе не было `pgg_load`.

Типовой цикл: `pgg_load` → `pgg_render`/`pgg_probe` с `file=` при необходимости → правка файла → сразу `pgg_render`/`pgg_probe` (F4).
